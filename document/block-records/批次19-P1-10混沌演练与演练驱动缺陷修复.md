## 一、剧本与断言设计

- **c21（Redis）**：kill redis-server（强杀，含数据丢失）→ 断言"HTTP 层可达（非 CONN_REFUSED）+ 请求快速失败 + DB 路径（admin reconcile）在停机期间可用" → runbook 命令恢复 + `rebuild-alloc` → **恢复后先对账（防半写残留）** 再下单。
- **c22（MySQL）**：`KILL` 平台连接 ×5 轮（25 连接）——服务级停机受非管理员 shell 权限限制（已如实标注）→ 探针无挂死 + 幂等键仅一单 + 对账 0。
- **c23（broker）**：kill broker（10911）→ 用户路径不受影响 → 停 sim 制造 OFFLINE 告警（去重后进 outbox、投递失败留存）→ **仅重启 broker（proxy 不重启）** → 投递自动恢复 → 重启 sim。

## 二、演练驱动的缺陷与修复（本批核心产出）

### 2.1 Redis 客户端无超时 → 故障级联拖死全站（最重，首跑实测暴露）
- 现象：Redis 停后平台 `CONN_REFUSED`、请求 60s 超时、纯 DB 路径一并瘫。
- 根因：`spring.data.redis` 未配超时（Lettuce 默认命令超时 60s）→ 调度/请求线程集体阻塞在死 Redis → 线程池与连接队列打满。
- 修复：`connect-timeout: 1s` + `timeout: 2s`；复跑：health 即时 503、下单 2s 快速失败、停机期间 reconcile 可跑。

### 2.2 DevSeeder 重启"错绑"在用电池 → 台账半写
- 现象：重启后对账检出 `cellId=4 batteryId=4 battery.cellId=null`。
- 根因：补全绑定的条件只查"cell 侧为空"，未校验电池在仓；**被用户取走的电池**（battery.cell_id=null）重启即被硬绑回仓（updateById 回写旧 update_time，掩盖变更时刻）。
- 修复：补绑前校验 `battery.cell_id == cell.id` + 反向自愈（错绑解除引用）。重启日志实证：`种子自愈：解除错绑 cellNo=4 batteryNo=BAT-0004（电池不在仓）`。

### 2.3 cmd-seq 运行时回退 → 撞 uk_cabinet_seq（恢复窗口下单 500）
- 现象：`Duplicate entry 'SWAP-C-001-2758' for key command_log.uk_cabinet_seq`。
- 根因：Redis 强杀重启加载旧 dump → `swap:cmd-seq:*` 回退；启动期对齐（seedSeqFromDb）只覆盖"启动时"，**运行时回退**无兜底。
- 修复：`nextSeq` 改单脚本原子（GET 现值与 DB `MAX(command_seq)` 取大 +1 + SET），每次调用自带 DB 兜底；Dao 增 `selectMaxSeq`；单测覆盖"回退以 DB 为底"路径。

### 2.4 workerId 租约 RDB 回退 → 持续 ERROR（操作项）
- 根因：owner=随机 UUID，RDB 回退的 owner=旧实例 UUID → 续期校验失败持续告警（保守设计，跨机安全语义正确）。
- 修复：owner 改稳定实例标识（ip:port）+ lease 夺回分支（仅夺本实例旧租约）；跨机冲突语义不变。

## 四、诚实边界

- **MySQL 服务级停机未实测**（非管理员 shell 无法安全停启 MySQL80 服务）：以连接级 KILL（5 轮）等效验证 Hikari 抖动恢复语义；服务级停机需提权环境补测。
- c21 停机期间下单 500 属预期语义（快速失败）；"恢复后立即下单"的成功依赖 Lettuce 重连完成窗口（本批剧本已含"恢复→对账→下单"顺序，并对恢复窗口的瞬时失败有幂等键兜底）。
- broker 停机期间 outbox `last_error` 为 `NotFoundException`（proxy 对 broker 断连的报错形态），恢复即消失；未深挖该错误码语义（不影响断言）。
