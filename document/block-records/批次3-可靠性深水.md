## 2. 设计取舍与边界（面试可深聊点）

- **延迟队列 at-least-once**：ZREM 即占有（多实例安全）；领取后实例崩溃任务丢失 → 靠业务扫描兜底（`OrderSweepTask` 保留）；处理器幂等（订单 CAS / 退款唯一键）。
- **重试分层语义**：查询失败→退避重试；设备已执行（lastCommandSeq≥seq）→按证据销账，其中"电池已取但事件链缺失"**不自动补记**（数量/时序无证据）→ EXCEPTION 交人工；未执行→同 seq 重发（设备幂等）。
- **资金 fail-fast**：回调验签失败/单据不存在直接拒绝；`swap.pay.secret` 未配置启动失败（与 admin token 同姿态）；入账以 CAS 命中为唯一闸。
- **MQ 保序**：sim 失败事件队首持留（不跳过重排——乱序会被平台序守卫当旧序拒=真丢数据）；平台并发度=1。
- **告警治理**：去重 SETNX + DB 时间窗兜底（Redis 丢失不重复入库）；限速只日志（不阻塞主流程）；批量离线合并阈值可配。
- **明确未做**：真实支付渠道、MQTT、Prometheus、双进程真部署（租约锁以单测+文档声明替代）；看护"首轮写基线"有一周期宽限。

## 4. 实战发现与修复（启动装配类，单测覆盖不到）

| 现象 | 根因 | 修复 |
|---|---|---|
| server 启动失败 `AlarmDao not found` | `@MapperScan` 未含 `com.swapops.server.alarm.dao` | `SwapServerApplication` 补扫描路径（`49f269f` 后补丁，见本批提交） |
| sim 启动失败 `MqEventReporter.<init>()` | 类有两个构造器且 Spring 未标注注入构造器 | 公开构造器加 `@Autowired` |
| g5 停 sim 无效 | PowerShell `$pid` 为自动只读变量，foreach 循环变量名 `$pid` 赋值被拒 | 脚本改用 `$procId` |
| g5 离线误报/漏报 | fast 模式 server TTL=5s < sim 心跳 10s → 全员闪烁离线 | sim fast 参数加 heartbeat-interval-seconds=2 |
| g5/g6 用户/电池耗尽重跑失败 | 脚本未选择干净用户、未动态找有电池的柜 | 选干净用户 + 动态柜/仓定位 |
