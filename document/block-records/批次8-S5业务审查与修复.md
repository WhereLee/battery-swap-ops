## P1（业务正确性，已修复）

### P1-1 跨用户幂等键碰撞 → 下单劫持 + 套餐冒领
- 事实：`swap_order.idem_key`/`user_plan.idem_key` 为全局唯一键，但 `byIdemKey` 不按 userId 过滤
  （SwapOrderService/PlanService）。
- 后果：用户 B 用 A 的 Idempotency-Key 下单 → 返回 A 的订单 → 控制器继续下发开仓指令
  （用 B 的 seq 覆盖 A 订单的 openCommandSeq，开 A 预占的仓），B 收到"无权访问"；套餐同理（B 拿到 A 的购买结果）。
- 修复：byIdemKey 加 userId 条件；唯一键撞车且查无本人单 → 抛"幂等键已被使用"。
- 测试：SwapOrderServiceTest.跨用户幂等键拒绝、PlanServiceTest 同步补（同 key 异用户不互见）。

### P1-2 SWAP 超期订单（OVERDUE）无出口 → 用户永久锁死 + 费用漏收
- 事实：全仓 OVERDUE 只有 TAKEN→OVERDUE 一条跃迁；`onBatteryIn` 只认 TAKEN/RETURN+OPENED；
  ACTIVE_STATUSES 含 OVERDUE → 用户无法再下单；计费只在 COMPLETED 跑 → 该次换电服务费/套餐扣次永久漏收。
- 修复（三件套）：
  1. `OrderEventService.onBatteryIn`：SWAP 归还接受 TAKEN/OVERDUE 双态（从实态 CAS 出发，
     超时费 elapsed 天然覆盖超期时段）；
  2. `OrderSweepTask` 新增 OVERDUE 超长未处置扫描（`swap.billing.overdue-max-hours`，默认 168h）
     → 转 EXCEPTION + 告警（退款补偿自动接管资金）；
  3. 对账①补 OVERDUE 卡滞核查（与扫描同阈值）。
- 测试：OrderEventServiceTest.超期订单还电完成、OrderSweepTaskTest（新增整档：兜底关闭/转人工/CAS 未命中不告警）。
