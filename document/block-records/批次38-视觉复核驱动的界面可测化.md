# 批次38 · 视觉复核驱动的界面可测化（可读性修复 + 三个浏览器门禁的自证与覆盖补齐）

> 日期：2026-09-19 ｜ 性质：**把"截图"这一唯一无度量的交付物变成可测门禁**，并修复它暴露出的真实缺陷
> 结论：管理台 10 条路由 270 个标签全部 ≥4.5:1、89 列表头/表体零错位、零裁切、零横向溢出；
> 三个浏览器/契约门禁改成**运行时自写证据**（此前 `_c35_out.txt` 是手工 tee 的，已与脚本脱节）。

## 一、为什么做

面试证据链里，"能跑起来的演示"排第一，而截图是**唯一没有机器判据**的交付物：`vue-tsc`、`vite build`、
`_c34`（HTTP 契约）、`_c35`（能否渲染）都不检查"**文字是否看得见**"。用户提出能否接入视觉模型做看图复核，
于是本批做两件事：**用视觉模型当探针找疑点，用 DOM 测量做判定**。

## 二、视觉模型当探针：可用的部分与不可用的部分（实测）

| 项 | 实测 |
|---|---|
| 通道 | `opencode-go` / `deepseek-v4-flash-vision-exp`，经 workflow 的 `agent(prompt,{provider,model})` 调用 |
| 读图 | 能准确读出页面结构、页签名、行数区间、表头文字（例：认出 `04-work-orders.png` 的 17 行工单、SLA 超期行底色、`待分诊` 状态） |
| **强制 JSON schema ⇒ 全部失败** | 11 个 agent 全返回 null（同提示词去掉 schema 后 11/11 成功）。**该模型不能用 schema 约束输出**，改为纯文本行格式自行解析 |
| 假阳性模式 | ① 把 12px 小字读不出，说成"标签渲染成空白方块"（成因是对比度 2.04–2.80:1，**结论对、归因错**）；② 把整页截图里的内容缺失说成"页面被折叠截断"（**这次是对的**，见 §四.2）；③ 把相邻列的裸数字认成"类型列是数字"；④ 声称"表头整体左移一列"（DOM 实测 89 列**零错位**） |
| 假阴性 | 读得出"守恒校验"块文字与 `代理 + 平台 = 基数`，但读不出 12px 页脚说明 |

**方法论结论**：视觉模型是**疑点生成器**，不是判定者。凡它提出的定量主张，一律回落到 DOM 测量；
它对**小字号**的判断不可采信，对**结构/缺失**的判断有提示价值。

## 四、三个"看着像应用缺陷、其实是门禁缺陷"的坑（本批最有价值的部分）

### 1. 剧本少跑了 6 项检查，而证据文件仍是旧的 31/31

`_c35_out.txt`（已提交）写 `PASS=31`，但同一次提交里的 `_c35_console.mjs` 只有 **25** 个 `check()`：
抽出 `_cdp.mjs` 时把 6 条 `B goto <path> renders (...)` 导航检查一起删了，而输出文件是**人工 tee 的一次性产物**，
没有任何命令能复现它。更糟的是同一处重构还引入了**静默 NaN**：新 `waitFor(expression, timeoutMs)` 被按老签名
传入了标签字符串，`Date.now() + "work-order detail"` = NaN ⇒ `while (Date.now() < NaN)` 一次都不循环 ⇒
**9 项检查在 0ms 内全红**，看起来像应用坏了。
处置：① `waitFor` 对非有限数值**抛错**（错误类型不得伪装成断言失败）；② 恢复 6 条导航检查并用
`(expression, label, timeoutMs)` 显式签名；③ **三个剧本改为运行时自写 `_*_out.txt`**（`_c34` 用 `Emit`+`Save-Evidence`，
`_c35`/`_c38` 由各 `.ps1` 包装器落盘）。详见 `document/pitfalls/check-coverage-lost-in-refactor.md`。

### 2. "整页截图"实际只有一屏 —— 之前的"假阳性"结论要更正一半

控制台外壳是**满高布局**，内容在 `<el-main>` 内部滚动，因此 `documentElement.scrollHeight` 恒等于视口高。
于是 `captureBeyondViewport` 只能截到一屏：结算详情的分账流水有 48 行，而"整页"截图**停在第 12 行**。
批31 曾把评审的"内容在折线处被截断"判为纯截图口径假阳性——**那一半判错了**：内容确实没进图里，
只是成因是**内部滚动容器**而不是窗口尺寸。
处置：`_cdp.mjs` 截图前把模拟视口按"内容高 + 外壳高"迭代到不动点（实测 11 张截图从恒定 1440×900
变成 1440×900…**2109**），并把真实捕获尺寸打进 `_c35_out.txt`。

### 3. 门禁自己也有假阳性（本次新增的两条判据）

评审两次声称"表头整体左移一列""表头被截断"，而裁切检查看不见这类问题（每个单元格自身都放得下）。
新增逐列判据（表头盒 vs 首行同序号的表体盒）后实测 **89 列全部 deltaLeft=0**；
`fixed="right"` 列用 `position:sticky` 绘制，在整页截图里会看起来错位——**这正是必须用数字而不是"再看一眼"来结案的那类主张**。
同时新增"整列不渲染可见文字"的度量，并区分 `innerText` 与 `textContent`：
前者暴露"绑定了值但看不见"（SOC 就是这样被抓住的），后者只说明"DOM 里有没有值"。
另：`/alarm` 的 `关联工单` 列前 20 行全是 `-`，经接口实测为**合法数据**——告警总表 4325 条、按时间倒序，
已关联工单的 6 条在深处分页，不是"列坏了"。

## 七、边界与如实申报

1. **`/login` 不在 `_c38` 覆盖内**：该页无表格、无标签，探针无物可测；其渲染与视口由 `_c35` B01/B21 覆盖。
2. **对比度门禁只覆盖 `.el-tag`**：按钮、链接、表头、分页、侧边栏等**未测对比度**。这是已知缺口，不是"全站 AA 达标"。
3. **`_c38` 的"整列无可见文字"是事实项不是门禁**：空列可能是合法数据（`关联工单` 已证），不能一概判红。
4. **视觉复核没有纳入 CI**：需要外部模型凭据，且该模型对 schema 不兼容，只作为本地评审工具；
   CI 里的判据是 DOM 测量（确定、可复现、零依赖）。
5. **截图不入 git**（`.local/b31-shots/`，gitignored），入库的是可复现脚本 + 统计文本。
6. **本批未做**：`swap-sim`/`swap-agent` 容器化、镜像漏洞扫描与 digest 固定、结案单生成弹窗、
   告警页"转工单"批量操作（仍为既有边界）。
