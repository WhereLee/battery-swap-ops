## 3. 自查：标准 vs 降级（明确取舍，不掩饰）

| 能力 | 行业标准 | 本项目现状 | 差距与影响 | 何时必须升级 |
|---|---|---|---|---|
| 熔断状态 | 跨实例共享（Redis/配置中心）/服务网格 | 每实例内存态 | 多实例下各算各的阈值 | 真多实例部署时 |
| 超时 | 异步 TimeLimiter/服务网格超时 | socket connect/read 超时 | 同步链路粗粒度；已够用 | 引入异步调用链时 |
| 缓存失效 | CDC/命名空间版本号 | Pub/Sub 全键广播 | 键量大时消息膨胀 | 缓存键量级 >10⁴ |
| 延迟双删 | binlog 驱动 | 固定 500ms 二删 | 窄窗口仍存在（TTL 收敛） | 强一致要求场景 |
| workerId 租约 | 续租失败停机自保（Leaf） | 告警继续 | 极端窗口有重复 ID 风险 | 多实例生产前 |
| outbox 中继 | CDC/Debezium/独立中继 | 同库轮询（5s） | 跨库不适用；事件延迟 ≤5s | 跨服务/跨库时 |
| 限流 | 网关/WAF + 动态配置中心 | 应用内注解静态 | Redis 故障窗口无限流；改动需发版 | 入口流量治理阶段（S5） |
| 池容量 | 压测数据定容 | 经验基线（Tomcat100/池16/DB20） | 未做容量验证 | S5 JMeter |
| 死锁重试 | 框架级全局 | 退款路径单点 | 其他路径依赖顺序/短事务 | 出现第二处真实死锁 |
| 可观测 | Prometheus/Grafana 告警面板 | admin 接口 + actuator + 日志 | 无历史曲线/自动告警 | S5 |
| dev 数据重置 | 种子数据幂等重置 | **未实现**（电池池被剧本耗尽后订单链路不可复跑） | 影响后续 E2E 剧本 | **尽快（S4 前）** |

## 4. 反思：同步阻塞与体验（用户要求，按风险排序）

1. **缓存重建串行**（影响最大）：热点键回源期间，同进程其他请求在本地锁上等待；跨实例未抢锁者固定 sleep 200ms 再重读。
   稳态下没问题，但**慢查询会放大成尾延迟**。改进：stale-while-revalidate（先回旧值、异步刷新）或异步等待——未做。
2. **outbox 中继轮询 5s**：告警到 Agent 的时延 = 0~5s。改成"入队后主动触发一次中继"（事件驱动轮询混合）可降到毫秒级，
   成本低收益中——未做（roadmap）。
3. **同步下行占线程**：开仓/查询是同步 HTTP，占用 Tomcat/调度线程；靠短超时+熔断舱壁兜底。
   彻底方案=下行异步化+MQ 回执，但会重写订单补偿语义——明确不做。
4. **限流每次请求一次 Redis RTT**：可接受；若要更低延迟可用本地令牌桶+Redis 批量充值（复杂度换延迟，暂不值）。
5. **数据库拿连接 2s 超时**：过载时用户看到 500（快速失败）而非长时间转圈——这是有意的体验选择；
   但对前台应有友好降级文案/重试提示（未做，属前端层）。
6. **优雅停机等待在途请求 30s**：用户侧正常（新请求被拒）；但本地 JVM 不退出（pitfall 已记），运维脚本需以端口释放为准。
7. **调度池 4 线程**：日终对账等长任务会占一格；任务看护能发现停摆，但**长任务阻塞其他任务**的窗口仍存在（per-task 隔离未做）。
8. **雪花/告警等 Redis 同步调用**：事件处理线程叠加多个 RTT；高 QPS 下应 pipeline/合并——未做。
