## 一、背景与目标

CI 自动跑（ubuntu-latest 自带 Docker，无需改 workflow 结构）。

## 三、设计决策

1. **镜像/参数对齐** `docker-compose.middleware.yml`：mysql:8.0（utf8mb4 / utf8mb4_general_ci）、redis:7。
2. **db/*.sql 全量经容器 initdb**：16 个迁移脚本含 DELIMITER 存储过程，无法走 JDBC，必须由容器
   `/docker-entrypoint-initdb.d` 的 mysql 客户端按名序执行；`Paths.get("..","db")` 相对模块目录解析
   （surefire/failsafe workingDirectory = swap-server）。
3. **夹具＝DevSeeder**（`swap.dev.enabled=true`）：确定性数据——4 柜 × 12 仓、前 6 仓满电（互指绑定）、
   25 用户（次卡剩 5 次 / 押金 9900，用户 1 押金 0）。不手工造数，与本地联调口径一致。
4. **容器与上下文共享**：容器在抽象类静态块启动（JVM 内一次）；三 IT 的 @SpringBootTest 配置相同
   → Spring 上下文缓存复用，IT 总耗时可控（CI 实测 IT-1 44s 含启动、IT-2/IT-3 亚秒级）。
5. **IT 柜隔离**：IT-1 用 SWAP-C-001、IT-3 用 C-002、IT-2 用 C-003——互不污染，顺序无关。
6. **IT-1 不拉起 sim**：`bindSeq` 直接落 openCommandSeq（指令台账销账由设备事件驱动覆盖；
   `markArrivedBySeq` 未命中仅 debug 不抛，已核实）；事件走 `DeviceEventService.handle` 单一入口，
   序守卫（条件 UPDATE）与跨代重放守卫真实执行。
7. **IT-2 动态基线**（base+1 / base）而非绝对 0：抗同 JVM 内其他 IT 的残影；注入"仓引用不存在电池"
   后精确断言只命中 `cell-battery-consistency` 一组（样本含 `cell→battery`）、总数恰好 +1，
   finally 恢复后回基线（对账只读，测后无残影）。
8. **IT-3 三重一致性断言**：恰好库存数成功 + 无重复授予 + 其余全拒；DB 侧 6 仓持锁且 lock_order_id
   互异并落在本次并发区间；Redis 侧可分配集合耗尽 + 每个成功单的预占快照与仓锁在位。
9. **surefire/failsafe 分工（本地无 Docker 的关键约束）**：surefire 默认 include 不匹配 `*IT`
   → `mvn test` 不碰容器；failsafe 默认 include 匹配 `*IT` → `mvn verify` 才跑；跳过用 `-DskipITs`。
10. **jacoco 关系**：failsafe 未配 argLine → IT 不插桩；`report@test` 在 test 阶段生成，
    `check@verify` 读的是单测报告——65% 门槛不受 IT 影响，也不被 IT 稀释。

## 五、踩坑

1. **Write 假失败 + 尾部残片**：ReconcileDetectIT 首次写入报 "unknown"（实际文件已写），
   尾部残留重复 `package` + 空类声明 → 编译报"需要 class、interface、enum 或 record"。
   教训：写文件报错先读文件确认实际状态，再决定重写还是修补。
2. **`mvn -pl swap-server` 缺 `-am`**：swap-contract 未 install 到本地仓库 →
   DependencyResolutionException（失败还会被本地仓库缓存）。多模块构建一律带 `-am`。
3. **`mvn clean` 撞运行中的 jar**：平台 8400 在跑锁住 target → clean 失败。
   纪律：停服 → clean test → package → 重启。
4. **gh JSON 中文标题**：`gh run list --json ... | ConvertFrom-Json` 在 PowerShell 5.1 因编码
   报"无效 JSON"——直接读文本输出即可。
5. **残留双实例**：发现 2 个未监听端口的 javaw（server/sim 各一，历史启动残留），
   与真实例写同一 gc.log。排查用 `netstat -ano` 定位真监听 PID，再按 PID 精确清理。
