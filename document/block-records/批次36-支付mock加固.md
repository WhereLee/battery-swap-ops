# 批次36 · dev 支付 mock 加固（AUD-7）

> 日期：2026-09-19 ｜ 性质：**独立审计驱动的安全加固**（dev-only 表面按生产标准收口）
> 结论：XSS 面关闭（白名单 + 明确"放宽时必须转义"的注释）；"自签即入账"入口限定回环，
> 且地址判定复用批次33 的**受信代理感知**解析器——反代后的远程请求不会被误判为本机。

## 一、缺陷（审计 AUD-7，两处，均需 `swap.dev.enabled=true`）

代码：`dev/PayMockController`（`@ConditionalOnProperty(swap.dev.enabled=true)`，**默认 false**）

1. **反射型 XSS**：`GET /pay/mock/page/{tradeNo}` 把路径变量原样拼进 HTML
   （`"<p>tradeNo: " + tradeNo + "</p>"`）。
2. **无鉴权的"造币"入口**：`POST /pay/mock/notify/{tradeNo}` 用服务端密钥自签后直接入账，
   没有任何调用方限制——任何能访问到该路径的人，只要知道 tradeNo 就能把充值单置为支付成功。

定位为 P2 而非 P0 的理由：默认关闭，且开启时也只是联调环境的门；但**"dev 开关被误开/误部署"**
恰好是最常见的真实事故形态，所以按生产标准收口。

## 二、修复

| 面 | 修法 |
|---|---|
| 支付页 | 单号先过字符集白名单 `^[A-Za-z0-9-]{4,64}$`，畸形输入在进业务前 400；**白名单内没有需要 HTML 转义的字符**，故不引入转义函数（并写明：一旦放宽白名单必须同时引入转义——避免留下"看起来安全但已失效"的旧转义代码） |
| notify | ① 只接受**回环**调用（`127.0.0.1` / `::1` / IPv6 回环）；② 客户端地址走 `ClientIpResolver`（批次33）——直连地址不在受信代理列表时完全不看 XFF，是受信代理时取 XFF **最右**非受信段，因此"经 nginx 反代的远程请求"会解析出真实远程地址并被拒；③ `result` 白名单 `SUCCESS|FAIL`；④ 每次 mock 入账打 WARN 日志（含解析出的客户端地址），便于事后分辨"这笔钱是真实渠道还是 mock 点的" |

## 三、验证

**单测** `PayMockControllerTest`（6 例，全部 PASS）：
- 合法单号渲染正确；畸形单号（`<script>`、带引号、路径穿越、空格、过短）一律 `RRException`；
- 本机调用放行，且断言**服务端自签的签名**确实是送进 `handleCallback` 的那个值（mock 与真实回调共用同一条验签入账路径）；
- 非本机调用拒绝，且 `handleCallback` **完全没被调用**（不是"先入账再报错"）；
- 受信代理形态：`XFF=203.0.113.7` + 直连 127.0.0.1 → 解析出 203.0.113.7 → 拒绝（**这条正是"反代不能把远程伪装成本机"**）；链路全受信时放行；
- 非法 `result` 与非法单号在业务之前被拒。

**实机探针**（本地平台，`swap.dev.enabled=true`）：

```
GET  /api/pay/mock/page/PAY123456                        -> 200（正常渲染）
GET  /api/pay/mock/page/%3Cscript%3Ealert(1)%3C%2Fscript%3E -> 400（白名单拒绝）
POST /api/pay/mock/notify/PAY123456?result=MAYBE         -> 400（result 白名单）
POST /api/pay/mock/notify/PAY123456?result=SUCCESS       -> 400（业务：支付单不存在）
```

后两条同时说明：本机调用**通过了**回环闸门（否则会是"仅限本机"的拒绝消息），
业务层再按单号不存在拒掉——即闸门没有把正常联调路径也堵死。

## 四、回归确认（不破坏既有剧本）

既有 `_c18`（分账）、`_c19`（渠道对账）、`_c20`（用户服务）三个剧本都用
`curl POST /pay/mock/notify/...` 从本机调用 → 仍走回环放行。本批**未改动**任何剧本。

## 五、边界与如实申报

1. **回环判定不是鉴权**：任何能登录本机的人都能调用 mock 入账。它与"dev 开关"是同一层信任模型
   （拿到 shell 的人本来就能改库），本批的目标是"关掉远程可达"，不是给 mock 网关加账户体系。
2. **没有实机验证"远程被拒"**：本地所有请求都来自回环，云上 nginx 反代形态需要公网入口
   （ufw 未放行，属用户拍板项）。该路径由单测里的"受信代理形态"用例覆盖。
3. 未做：mock 网关的独立 token/白名单 IP 配置（若要上公网演示，应先做这个，而不是靠回环）。
