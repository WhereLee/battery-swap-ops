# 批次41 · 界面门禁扩面（弹窗 / 占位符 / 非文本边界）

> 日期：2026-09-20 ｜ 性质：**继续收口 `_c38` 自己声明的边界**（批次38 声明"不覆盖弹窗"，批次39 声明"未测非文本对比度"）
> 结论：探针新增**弹窗测量**（按按钮文本打开、按元素作用域测量）后立刻抓到一个真缺陷——
> **占位符文字 2.30:1**（批次39 修了 `--el-text-color-secondary`，漏了 `--el-text-color-placeholder`，
> 而页面上没有占位符，只有打开表单才会出现）；同时把**非文本边界**也量了出来（175 个边界、15 个低于 3:1），
> 但**刻意不设为门禁**并把理由落档。最终 `_c38` 10 页 + 1 弹窗 hardFailures=0。

## 一、为什么做

批次38/39 的边界申报里留了两条：

> `_c38` 不覆盖弹窗/抽屉（探针不打开对话框，表单校验红字与 message 提示不在覆盖内）
> 对比度只覆盖文字：图标、边框、图表色块的对比度（WCAG 1.4.11 非文本对比）未测

这一批把第一条补上（弹窗真能测），第二条**测量但如实不设门禁**（理由见 §四）。

## 二、实测：弹窗一开，立刻暴露一个新缺陷

新增"弹窗轮"：对每个弹窗按**按钮文本**找到打开者 → 点击 → 等 `.el-dialog` 可见 →
**以该弹窗元素为作用域**重新跑同一套测量（Element Plus 把弹窗 teleport 到 `<body>`，
页面在弹窗后面仍然渲染，若仍按整页测量会把页面数字重复计一遍，也说不清哪条数值来自表单）。

首跑立刻报出：

```
--- dialog: 从告警创建工单 (/alarm) ---
      low text 2.3:1 (need 4.5) "留空＝按告警类型自动派生" span color=rgb(168,171,178) bg=rgb(255,255,255) font=14px
```

`rgb(168,171,178)` = `#a8abb2` = **`--el-text-color-placeholder`**。

| 判定项 | 实测 |
|---|---|
| 弹窗内 select 占位符（真实元素 `.el-select__placeholder`） | **2.30:1**（14px，门槛 4.5:1） |
| 页面输入框占位符（`::placeholder` 伪元素，探针本轮新增测量） | **2.30:1**（`/orders` 的"订单号（模糊）"、`/cabinets` 的"柜编号（模糊）"） |

**为什么前两轮没发现**：批次39 只修了 `--el-text-color-secondary`，而占位符用的是另一个令牌；
且**页面上没有占位符**（占位符只在输入框/表单里），所以走遍 10 条路由也测不到——
这正是"扩面"而不是"重测"才能发现的东西。

修法（`global.css`）：`--el-text-color-placeholder: #6f747c`（4.70:1）。
**窗口很窄，如实写下来**：占位符必须**比正文值色更浅**（`--el-text-color-regular` `#606266` = 6.11:1）
才能让"已填/未填"看起来不同，同时自己又要 ≥4.5:1 ⇒ 亮度上限 0.1833，而 `#6f747c`（4.70:1）
几乎是"还能通过 AA 的最浅灰"。代价：已填与未填的区分更多靠**占位符文字随输入消失**，
而不是靠明显的颜色差——这是白底上满足 AA 的必然取舍。

## 三、探针自身的两个实现坑（都记进注释了）

1. **模板字符串里不能写反引号**：注释里写 `` `body *` `` 直接把整个探针字符串提前终止 ⇒
   `SyntaxError: Unexpected identifier 'body'`。批次38 踩过一次（注释里的反引号），本轮又踩一次——
   已在代码里写明 "never write backticks in this comment block"。
2. **`root.querySelectorAll('body *')` 在弹窗作用域下恒为空**：弹窗不是 `<body>` 的后代。
   改为 `scopeIsPage ? document.body : root`。这条不改的话，弹窗轮会"全绿"——因为**一个元素都没测到**，
   这是最危险的一种假绿。

另修一处**自己写的假绿**：占位符样本最初是在 `lowContrastText` 计算**之后**才推进数组的，
于是占位符失败被"测量了、单独报告了、但没进门禁"。已把顺序前移，并在注释里写死这条纪律：
**进不了门禁的测量等于注释，不等于检查。**

## 四、非文本边界（WCAG 1.4.11）：测量并报告，刻意不设门禁

探针顺带量了 175 个 UI 边界的"边界色 vs 相邻底色"：

| 元素 | 实测 | 说明 |
|---|---|---|
| 默认/朴素按钮（`.el-button`，如"刷新""返回列表"） | 边框 `rgb(220,223,230)` 对 `rgb(245,247,250)` = **1.24:1** | `--el-border-color` `#dcdfe6` |
| 卡片（`.el-card`） | 边框 `rgb(228,231,237)` 对底 = **1.15:1** | `--el-border-color-light` `#e4e7ed` |
| 主按钮/表头/单元格 | 5.17–6.15:1 | 已在批次39 修好（主色令牌 + 表格文字令牌） |
| 弹窗内按钮 | 取消 1.33:1 / 创建 5.55:1 | 同上 |

**为什么不改**：① WCAG 1.4.11 的适用范围本身是判断题——输入框/卡片同时由标签、位置与底色区分，
边框不是唯一的识别手段；② 修它意味着把**全站边框**整体压深（`--el-border-color` 是所有表单控件的边框），
属**视觉设计决策**而不是缺陷修复，按约定这类范围决策留给用户拍板。
所以本轮**只测量、只报告、落档数字**，门禁里明确打印 "reported, deliberately NOT a gate condition"。

## 七、边界与如实申报

1. **只覆盖"能打开的那个弹窗"**：其余三个因数据/页签原因 SKIP（见 §五），不是"弹窗都没问题"的证明。
2. **非文本对比度不设门禁**（§四），只报数字；修它属视觉设计决策。
3. **`el-message`/表单校验红字仍未覆盖**：它们是运行时插入的全局组件，需要触发一次失败操作（例如提交非法表单）才能测到。
4. **悬停/聚焦/激活态仍不测**（探针读的是静止态）；批次39 已主动修过 hover 压深，但同样没有门禁保护。
5. **假绿的两种来源已修**（§三.1/§三.2），但同类风险仍在：**作用域选错会让测量变成空集而不报错**——
   门禁的 `dialogNotReady` 只能证明"弹窗打开了"，不能证明"弹窗里真测到了东西"；
   本条记录在案，后续若要加固应加"弹窗内元素数下限"的自检。
