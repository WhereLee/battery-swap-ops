## 二、验收证据（实测）

- **单测 77/77 绿**（契约 4 + 平台 66 + 模拟器 7）；新增 8 个测试类覆盖分配/事件/计费/下单/钱包/套餐/会话/管理端鉴权。
- **剧本2（GATE-2 PASS）**——用户 13800000001 全链路：
  - TAKE：开仓→取电→COMPLETED；`payType=PLAN`；押金 0→9900；次卡 5→4；
  - SWAP：取满电（BAT-0003）并归还 BAT-0002 → COMPLETED；`returnBatteryNo`=归还电池；
    持有人转移（新电池绑定用户）；次卡 4→3；
  - RETURN：还电池入仓 → COMPLETED；`feeFen=0`（退租无服务费）；押金 9900→0（入余额）；次卡保持 3。
- **剧本3（GATE-3 PASS）**——20 用户并发抢 SWAP-C-002（6 块满电）：
  - 成功 6（=库存上限）/ 失败 14 全部 HTTP 400（"暂无可换的满电电池"）；
  - 成功单仓位/电池**零重复**（6 个不同 cellNo / batteryNo）；无 5xx、无超卖。

## 三、关键设计落点

1. **分配并发**：Lua 弹仓即打 Redis cell-lock；DB 条件更新 `lock_order_id IS NULL` 为最终判官；内容失效（电池非满电/仓位不符）回滚重试；超时/取消/下发失败统一 release + 集合刷新。
2. **事件会话关联（S2 关键协议语义）**：同一开门会话内的 BATTERY_OUT/BATTERY_IN 回带该次 OPEN_CELL 的 `commandSeq`（sim 侧会话保鲜 5 分钟）——设备无需知道 orderId，订单域据此精确推进；无 seq 事件只走设备台账。
3. **计费幂等**：`payment_record(order_id, payment_type)` 唯一键是资金动作闸；订单 CAS 到终态后才计费；TAKE 押金余额转押金、RETURN 退押金、SWAP 超时费（余额→押金依次抵扣，不足记欠费日志——S3 告警接管）。
4. **事务边界**：下单事务只做校验/落单/预占；开仓 HTTP 在事务提交后发送，失败补偿（释放预占 + CANCELLED[SEND_FAILED]）——不在 DB 事务里等待网络。
5. **管理端鉴权**：`swap.admin.token`（SWAP_ADMIN_TOKEN 注入）未配置启动即失败；`/admin/**` 常量时间比对。

## 四、发现与处置

1. **Redis MISCONF（环境）**：本地 Redis 以默认工作目录启动，RDB 落盘失败导致所有写命令被拒（500）。
   处置：`redis-server ... --dir F:\Redis` 重启修复；平台按 500 表现暴露（不吞错），定位快。
2. **PS 5.1 脚本中文正则失效（工具）**：脚本内中文字面量按 GBK 读出成乱码，`-match "暂无可换"` 永不命中。
   处置：断言改为 HTTP 状态码（400）；重申约定——**脚本内容全英文**。
3. **PS 5.1 写文件带 BOM / GBK 重编码（工具，已固化为坑位）**：`Set-Content -Encoding UTF8` 写入 BOM 使
   javac 报 `非法字符 '\ufeff'`；`Get-Content` 默认 GBK 读 UTF-8 中文导致重写损坏。坑位：
   `document/pitfalls/ps-utf8-bom-and-mojibake.md`；修复用字节级剥离 BOM。
4. **并发剧本口径修正**：S0.6 草案写"12 块满电"，实测种子为每柜 6 满电（另有 6 空仓供 RETURN）——
   剧本按真实种子断言"成功数 ≤ 满电库存"，同时证明零超卖。S0.6 已加实测注记。
5. **幂等重放语义**：下单/购套餐均以 DB 唯一键（`swap_order.idem_key` / `user_plan.idem_key`）兜底，
   Redis 仅作加速；并发同 key 冲突时回读已存在记录返回（不重复扣款）。
