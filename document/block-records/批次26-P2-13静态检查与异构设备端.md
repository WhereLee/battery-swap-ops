## 二、异构设备端（P2-13-3，协议开放性的正面回答）

**动机**：sim 是 Java 且与平台共享契约模块，"自产自销"的质疑无法自证协议开放。

`scripts/verify/batch26/hetero_device.py`（Python 3.13 标准库，零第三方依赖、与平台零共享代码）：
- HMAC canonical 独立实现（event/heartbeat/command/query 四类，常量时间比对）；
- 上行：单发送线程 + 有界队列 + **队首持留** + 退避重试（与契约 §7 保序铁律同构）；
- 下行：`/cmd` 验签（伪造 401）+ **指令幂等**（seen_commands，重放 duplicate）+ 异步开门；
- **开门会话语义**（契约 §5）：开门记会话（cellNo→commandSeq，5 分钟保鲜窗）、
  BATTERY_OUT 回带且保留、BATTERY_IN 回带且终结（对齐 sim 语义）；
- 设备记忆：bootId（每启新代际）+ eventSeq（**持久化**，重启续增）；
- 物理动作模拟：`/local/remove|insert`（模拟骑手取放 + RFID 读编号），
  fixture 电池编号与平台种子同公式 `BAT-%04d((index-1)*cells+cell)`；
- 优雅退出：SIGTERM 排空队列 + 持久化 state。

## 四、踩坑（三个真问题，头两个是最有价值的收获）

### 1. 平台下行 `chunked` 被最小设备栈读空（首跑 11/16 的根因）
- 现象：下单 400 `柜拒绝指令: not my cabinet: None`（Python 的 `None` 暴露消息来自设备），
  设备日志却毫无请求痕迹；订单被补偿关闭。
- 定位：用**探针假设备**（discard 服务 dump 原始请求）抓到平台实际发出的报文：
  `Upgrade: h2c` + `Transfer-encoding: chunked`、**无 Content-Length**。
  Python 标准库 `http.server` 只认 `Content-Length` → 读到空 body → `payload={}` → `cabinetNo=None`。
- 根因：`JdkClientHttpRequestFactory` 的流式 body（长度未知 → chunked）+ JDK HttpClient 默认协商 h2c。
- **为什么没早暴露**：sim = Tomcat、单测 = JDK HttpServer——两者都自动解析 chunked；
  只有"最保守设备栈"会踩中——**这正是异构测试的价值：它不共享任何便利假设**。
- 修复（平台侧，主修）：`CommandDispatchService.postJson` 改为显式 `HTTP_1_1` +
  `BodyPublishers.ofString`（**自带 Content-Length**）+ 手写异常映射（保持
  `RestClientException`/`HttpStatusCodeException` 语义不变）。
- 回归门禁：单测新增"**Content-Length == body 字节数 且 无 Transfer-Encoding**"断言（见 `CommandDispatchServiceTest`）。

### 2. 设备端会话语义缺失（二跑 14/18 的根因）
- 现象：`BATTERY_OUT` 已到平台（http=200、台账推进）**但订单不推进**；
  TAKE 挂 OPENED → RETURN 下单被"进行中订单"拒（400）。
- 根因：设备端 `local_remove/insert` 上报事件**未回带本次 OPEN_CELL 的 commandSeq**（契约 §5 会话关联：
  "订单域据此精确推进"）——事件能到平台 ≠ 业务能推进。
- 修复：按 sim 语义实现（开门记会话 / 取电保留 / 还电终结 / 5 分钟保鲜窗）。
- 教训：异构实现要**逐条对照契约的字段语义**，而不是"事件发出去了就算通了"。

### 3. 剧本恢复段 `| Out-Null` 管道卡死（两轮 900s/1200s 超时的根因）
- 现象：teardown 后 `start-server-mq.ps1`/`start-sim-mq.ps1` 的子 powershell 调用不返回，
  剧本永远到不了结尾（平台已起、sim 未起）。
- 定位实验：同一脚本**无管道 0.34s 返回**；**有管道**要等"被启动的长活 JVM 退出"
  （java 因端口冲突快退时 20.8s；java 常驻则永不返回）。管道 EOF 要等所有写端关闭，
  经 javapath shim 转发的 JVM 持有可继承句柄。
- 修复：启动长活进程一律**裸调用（不接管道）**；恢复后用"平台+sim 双 health 绿"的有界等待验证
  （`[verified=True]`）。
- 附带加固：恢复/清理段去 WMI 依赖（`Get-CimInstance` 改 netstat 端口法）；剧本第 1 步扩为
  清 8600（防诊断探针残留）。
