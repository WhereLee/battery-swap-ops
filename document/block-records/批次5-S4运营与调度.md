## 2. 关键设计与复用

- **SLA 复用延迟队列**：工单超时 = 延迟任务 + 终态撤销 + 超时置位告警（与订单三段计时器同构）；
- **缓存写路径闭环**：套餐/站点变更 evict（L1+L2+PubSub），`_c9` 实测"改完即见"；
- **看板与分配同源**：站点可用率读分配池（Redis），保证"看板能换=真的能换"；
- **资产结构变更重建池**：柜/仓/电池任何登记变更后 `rebuildFromDb()`（幂等）；
- **删除=引用保护**：站（有柜）、柜（有电池/锁）、电池（在仓/在持/订单引用）一律拒绝，宁可拒绝不级联删。

## 4. 取舍与边界（如实声明）

- 工单：自动转单/智能分诊/分级催办未做（人工从告警转单）；操作人暂固定 "admin"（无 RBAC 用户体系）；
- 用户管理：无改手机号/删号（实名合规场景另议）；停用不清 token（resolve 实时校验，语义更简单）；
- 资产登记：secret 由管理员写入（业务数据），响应一律脱敏、日志无明文；批量导入/导出、独立仓登记不做；
- 看板：无趋势/环比/下钻（S5 报表阶段）；缓存 60s 陈旧已声明；
- 实施偏差：原计划 B2.1/B2.2 分两笔提交，实际合并为一笔（服务层同文件改动，拆提交会造中间态）；功能与证据未减。
