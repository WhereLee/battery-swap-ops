# 批次39 · 设计令牌级对比度收口（把"只有标签达标"变成"全站文字达标"）

> 日期：2026-09-19 ｜ 性质：**收口批次38 自己声明的边界**（当时门禁只覆盖 `.el-tag`）
> 结论：把对比度门禁从"标签"扩到**全部叶子文字元素**后，发现失败**根本不是标签特有的**——
> 两个 Element Plus 设计令牌击穿了整个次要文字层、全部链接、全部表头标签与主按钮；
> 令牌级修复后 **1936 个文字元素 + 270 个标签在 10 条路由上全部达标**，门禁同时升级为硬门禁。

## 一、为什么做

批次38 的边界申报里写着一条：

> 2. **对比度门禁只覆盖 `.el-tag`**：按钮、链接、表头、分页、侧边栏等**未测对比度**。
>    这是已知缺口，不是"全站 AA 达标"。

自己声明的缺口自己补。扩大覆盖面不需要新工具，只需要把"按固定选择器列表测"换成
"**遍历所有持有自身文本的可见叶子元素**"——这样**没人想到的组件也会被覆盖**。

## 二、实测：失败集中在两个令牌（不是几十个组件）

扩面后第一批实测（修复前，每页 7–12 处不达标，且在 10 条路由上**重复出现同一批选择器**）：

| 令牌 | 原值 | 实测对比度 | 波及面 |
|---|---|---|---|
| `--el-text-color-secondary` | `#909399` | **2.87:1**（on `#f5f7fa`）/ **3.08:1**（on white） | 页面副标题、`共 N 条`、提示语、时间线时间戳、**表格表头**、空态文案、`.text-muted`——**整个次要文字层** |
| `--el-color-primary` | `#409eff` | **2.78:1** | **双向都挂**：作为文字压在白底（链接 / 选中页签 / `el-link`），又作为底色被白字压（主按钮 / 选中单选按钮 / dark 标签） |
| `--el-color-warning` 作文字 | `#e6a23c` | **2.19:1** | 告警页 `建工单` 文字按钮（白字压 warning 同样是 2.19:1） |
| 侧边栏自绘色 | `#8492a6` / `#5c6b7f` | 4.43:1 / **2.57:1** | `.brand-sub`、`.aside-foot`（深底上要**调亮**而不是调暗） |

**关键判断**：`#409eff` 一个值同时决定"文字压白底"和"白字压它"，两者的合格条件是**同一个**
（相对亮度 ≤ 0.1833）。所以**一个令牌就能同时修好链接与主按钮**，不需要逐组件打补丁。

## 三、修法（`swap-web/src/styles/global.css` 令牌级 + 少量组件级）

```css
:root {
  --el-text-color-secondary: #5d6269;   /* 6.06:1 on white, 5.62:1 on #f5f7fa */
  --el-color-primary: #1668c1;          /* 5.07:1 两个方向都成立 */
  --el-color-primary-light-3..9 / dark-2: 按 EP 自己的公式重算
}
```

- **light-N 按 Element Plus 的公式重算**（`light-N = mix(primary, white, N*10%)`，用 `#ecf5ff` 反推验证过公式），
  否则会出现"新主色 + 旧浅色族"的脏配色；
- **hover/active 单独压深**：默认 hover 用 `light-3`，白字压 `#5c95d4` 只有 3.13:1；
  改成 `#1253a0`（7.58:1）。探针只测静止态，所以这一条是**主动**修的，不是被门禁逼出来的（已申报）；
- **语义按钮**（warning/success/danger/info）按同一套色板压深，且**作用域限定在按钮**：
  语义色同为图表/进度条填充色，全局改会改变图形语义，而这次的问题是**文字**；
- 硬编码的 `#909399`（`.text-muted`/`.page-subtitle`/`.metric-caption` 与 3 个视图）统一改为
  引用 `var(--el-text-color-secondary)`，**单一来源**，避免下次改令牌时漏掉自绘样式；
- 侧边栏两处深底浅字**调亮**（`#a8b3c4` 6.61:1、`#9aa7b8` 5.73:1）——深色背景上的修法方向与浅色相反。

## 四、门禁升级（同时是本次的方法论收益）

`_c38_ui_probe.mjs` 新增第 7 条硬门禁：

```
PASS  every text element reaches its WCAG threshold (0 below, 1936 elements scanned)
```

实现要点（值得复用的三条）：

1. **遍历叶子文字元素**而不是手写选择器列表；
2. **按 WCAG 1.4.3 分级**：默认 4.5:1，**只有大字号**（≥24px，或 ≥18.66px 且加粗）才允许 3:1；
3. **豁免项显式跳过**：`[disabled]` / `.is-disabled` / `aria-hidden="true"`（WCAG 同样豁免），
   否则禁用态会把门禁永远染红；
4. 按 `(选择器, 颜色, 阈值)` 去重后报告，否则输出是同一行表格样式的 400 份副本。

## 六、视觉复核本轮的两条结论（一真一假）

1. **真（分类要更新）**：它两次指出看板"不可用站点（1）"卡片**内容几乎为空**。
   实测：卡片内确有 `ST-E2E2-224621` 标签，112×24px、对比度 **8.24:1**——内容在，是
   `_c35` 整页截图被下游缩放后 12px 文字对它不可读 + **一张满宽卡片只放一个标签显得空**。
   归类：**渲染无缺陷，但版式确实稀疏**（记为可选优化，未擅自改版式）。
2. **假**：把"标签读不出"再次表述为"渲染成占位符/破图"，同批次38 的假阳性模式。

## 七、边界与如实申报

1. **hover/active/disabled/focus 态不进截图**，探针只测静止态；本次 hover 是主动修的，
   但**没有门禁保护**（要测得用 CDP 派发鼠标事件，列为可选后续）。
2. **弹窗/抽屉未测**：探针不打开对话框（表单校验红字、`el-message` 提示等不在覆盖内）。
3. **深色模式未做**（项目无 dark 主题），故未验证 `html.dark` 下的令牌。
4. **对比度只覆盖文字**：图标、边框、图表色块的对比度（WCAG 1.4.11 非文本对比）未测。
5. 看板"不可用站点"卡片版式偏空**未改**（属版式决策，留用户拍板）；本轮只做可访问性收口。
