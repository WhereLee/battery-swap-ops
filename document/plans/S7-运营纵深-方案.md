## 二、WP-0：既有资金缺陷修复（先行独立提交）

### 缺陷（审查实证）
1. **押金二次退款**：`RefundService.REFUNDABLE_TYPES` 含 `DEPOSIT`（RefundService.java:32-33），
   而 RETURN 完成时 `BillingService.charge:56-59` 已用 `refundDeposit()` 把押金退入余额；
   对同一 TAKE 订单再调 `admin/refund`，`refundableAmount` 仍返回 9900 → 二次退现（管理端可达）。
2. **管理端退款无状态约束**：`AdminRefundController.java:36-54` 对任意状态订单可退（含 COMPLETED）。
3. **人工退款无操作人留痕列**：`refund_record` 无 operator 字段（A 的 admin_op_log 记动作，
   但退款单本身应留操作人——**本 WP 加列**：`operator_id/operator_name`，db/11 一并）。

### 修复
- `REFUNDABLE_TYPES` 移除 `DEPOSIT`；注释与文档声明"**押金退还只走退租 RETURN 流程（refundDeposit）**"；
- `AdminRefundController` 增加状态白名单：仅非终态或 EXCEPTION 单可人工退（COMPLETED 单拒绝，文案指向冲正）；
- `refund_record` 增 `operator_id/operator_name`，refund 入口传入（WP-0 阶段先留空，A 接通 context）；
- 单测：押金单不再计入可退；COMPLETED 拒绝；回归既有 RefundServiceTest。

## 三、WP-A：管理端身份、权限与审计

### A1 现状事实（核验确认）
- 新项目无任何 RBAC：`AdminTokenFilter`（servlet 过滤器，`@Order(HIGHEST_PRECEDENCE+10)`）静态 token 拦 `/admin/`；
  无管理员账号/角色/审计表；`handler`=UserContext.get()（admin 态恒 null）；工单人工流转 operator 固定 "admin"
  （CREATE/SLA 为 "system"）；调拨 operator / 建议单 confirmer / **建议单 proposer** 均为客户端可传参。
- 壳子参照物齐备：SecurityConfig(@EnableMethodSecurity)/AuthTokenFilter/SysLogAspect（GET 默认不落，
  响应脱敏）/PasswordCodec(BCrypt)/TokenGenerator(SecureRandom 32hex)。

### A2 设计
- **身份模型（`admin_user`，db/11）**：id/username(唯一)/password_hash(BCrypt)/real_name/
  role(SUPER/OPS/FINANCE/SUPPORT)/status/last_login_time/create/update。
- **权限码表（全量覆盖 18 个 controller / 61 端点，核验后补全）**：

  | 域 | 权限码 | SUPER | OPS | FINANCE | SUPPORT |

  | 告警 | `admin:alarm:read` / `admin:alarm:handle` | ✓✓ | ✓✓ | ✓read | ✓✓ |
  | 工单 | `admin:work-order:read` / `:manage` | ✓✓ | ✓✓ | – | ✓✓ |
  | 资产(站/柜/仓/电池) | `admin:asset:read` / `:manage` | ✓✓ | ✓✓ | – | ✓read |
  | 调拨 | `admin:transfer:read` / `:manage` | ✓✓ | ✓✓ | – | – |
  | 充电策略 | `admin:charge-policy:read` / `:manage` | ✓✓ | ✓✓ | – | – |
  | 套餐 | `admin:plan:read` / `:manage` | ✓✓ | – | ✓✓ | – |
  | 订单 | `admin:order:read` | ✓ | ✓ | ✓ | ✓ |
  | 退款 | `admin:refund:create` | ✓ | – | ✓ | – |
  | 结算 | `admin:settlement:read` / `:manage` | ✓✓ | – | ✓✓ | – |
  | 渠道对账 | `admin:recon:read` / `:import` / `:handle` | ✓✓✓ | – | ✓✓✓ | – |
  | 用户(骑手) | `admin:user:read` / `:manage` | ✓✓ | ✓read | ✓read | ✓read |
  | 欠费 | `admin:arrears:read` / `:waive` | ✓✓ | – | ✓read | ✓✓ |
  | 优惠券 | `admin:coupon:read` / `:manage` | ✓✓ | – | ✓✓ | – |
  | 报表 | `admin:report:read` | ✓ | ✓ | ✓ | – |
  | 看板 | `admin:dashboard:read` | ✓ | ✓ | ✓ | ✓ |
  | 缓存/限流运维 | `admin:cache:read` / `admin:ratelimit:read` | ✓✓ | ✓✓ | – | – |
  | 对账(既有) | `admin:reconcile:read` / `:run` | ✓✓ | – | ✓✓ | – |
  | 运维端点 | `admin:ops:run` | ✓ | ✓ | – | – |
  | Agent 建议单 | `admin:suggestion:read` / `:manage` | ✓✓ | ✓✓ | – | – |
  | 代理商管理 | `admin:agent-mgmt:read` / `:manage` | ✓✓ | – | ✓✓ | – |
  | 管理员管理 | `admin:admin:manage` | ✓ | – | – | – |

  （命名去歧义：建议单=`suggestion`，代理商=`agent-mgmt`；既有 `/admin/reconcile` 归 `admin:reconcile:*`。）
- **登录与会话**：`POST /admin/auth/login`（账号+密码，BCrypt，IP 限流）→ SecureRandom 32hex →
  Redis `swap:admin:token:{token}`（TTL 12h）→ `POST /admin/auth/logout` 吊销。
- **鉴权链（Spring Security）**：
  - `SecurityFilterChain` `securityMatcher("/admin/**")`（仅管理面走安全链；设备/用户/dev/actuator 零影响）；
  - **旧 `AdminTokenFilter` 退役**：删除该类，逻辑并入 `AdminAuthFilter`（登录路径 `/admin/auth/login`
    豁免；会话 token → 真实身份；静态 `swap.admin.token` → break-glass）。

    > 关键（审查发现）：旧过滤器是 servlet 过滤器且 Order 极高，若保留会先于 Security 链 401 掉登录请求——
    > 必须退役；`AdminTokenFilterTest` 迁移为 `AdminAuthFilterTest`。
  - 401/403 统一 JSON：`AuthenticationEntryPoint` + `AccessDeniedHandler` + **`RRExceptionHandler` 增加
    `AccessDeniedException` 分支返回 403**（否则被 `handleOther` 吞成 500——审查发现）；
  - `@PreAuthorize` 挂全部 /admin/**；排除 `UserDetailsServiceAutoConfiguration`；CSRF/会话关闭。
- **操作审计（`admin_op_log`，db/11）**：`@AdminLog(action)` + AOP（参数/响应脱敏截断，
  照壳子 SysLogAspect；**仅写操作**，GET 不落）；字段：admin_id/username/action/method/uri/params_json/
  result_code/error/duration_ms/ip/create_time。**登录端点审计需脱敏 password**；限流切面在外层（@Order 约定）。
- **审计覆盖性约束（审查建议）**：反射单测——扫描 `/admin/**` 全部写方法（POST/PUT/DELETE），
  断言均有 `@PreAuthorize` + `@AdminLog`，且权限码存在于 `AdminRole` 枚举（防实现期漏挂）。
- **身份接通**：告警 handler=adminId；工单人工流转 operator=username；调拨/建议单 operator/confirmer
  **改取 context**（客户端参数保留兼容但忽略，记日志；`agent_action.proposer` 同样改为 context）；
  refund operator（WP-0 加列）接通；无业务留痕列的端点（charge-policy/ops/资产 CRUD）由 admin_op_log 承担。
- **break-glass 语义（明确定义）**：静态 token=SUPER 全权、审计 username=`bootstrap`、不可吊销、
  不受登录限流；文档写明轮换流程（换 env + 重启）与"仅运维/脚本使用"。
- **不做**：数据权限（按站点过滤，DataFilterAspect 模式留档后置）、动态菜单（无前端）。

### A3 交付物
db/11（admin_user / admin_op_log / refund_record 加列）+ AdminAuthFilter/AuthService/AdminContext/
AdminRole/AdminAuthController/AdminLogAspect + 全部 admin controller 挂注解 + 反射覆盖性测试 +
权限矩阵单测 + `_c17_rbac` 剧本（含 401/403 双断言、静态 token break-glass、登出吊销、审计落库）+

## 四、WP-C：渠道对账 T+1

### C1 模型（db/13）
- `channel_bill`：id / bill_date / **channel**(默认 MOCK；审查建议：现在就加，多通道零改造) / trade_no /
  amount_fen / status(SUCCESS/CLOSED) / imported_at；UNIQUE(bill_date, channel, trade_no)。
- `recon_diff`：id / bill_date / channel / trade_no / diff_type(CHANNEL_ONLY/PLATFORM_ONLY/
  AMOUNT_MISMATCH/STATUS_MISMATCH) / detail / status(OPEN/HANDLED/IGNORED) / handled_by/handled_time/
  remark / create_time；UNIQUE(bill_date, channel, trade_no, diff_type)。

### C2 流程
- 账单生成（dev-only，挂进既有 `PayMockController`，路径 `pay/mock/bill/export?date=`）：CSV
  （bill_date,trade_no,amount_fen,status），支持 `anomaly=` 注入差异（missing/extra/amount/status）；
- 导入：`POST /admin/recon/import`（CSV 文本，事务内"先清当日（同 channel）再插"，幂等）；
- **对账=幂等重建**（审查修正）：`reconcile(date)` 重算当日差异——OPEN 差异按重算结果 upsert/删除，
  **HANDLED/IGNORED 保留为处置留痕**（重导不产生"账单已平但差异单仍 OPEN"的假告警）；
- 差异分类口径：渠道 SUCCESS ↔ 平台 pay_order SUCCESS+入账流水；渠道 CLOSED ↔ 平台 CLOSED；
  平台 WAIT 不参与；渠道独有/平台独有/金额不符/状态不符四类；
- 日报 `GET /admin/recon/report?date=`；差错处理 `POST /admin/recon/diff/{id}/handle`（CAS + context 留痕）；
- 任务：`ChannelReconTask` 每日 02:40 对账昨日（账单未导入→记日志+看护 beat）；OPEN 差异>0 →
  `AlarmType.CHANNEL_RECON_DIFF`；不变量⑫（渠道对账零 OPEN，日报口径）。

## 五、WP-D：用户服务与营销

### D1 用户报障 → 工单
- `work_order` 增列（db/14 幂等 COLUMNS 守卫 ALTER）：`source`(ALARM/USER_REPORT 默认 ALARM) /
  `reporter_user_id` / `description`；`alarm_id` NULL 语义不变（MySQL 唯一键允许多 NULL，已核验）；
- 用户端 `POST /user/report`：限流 + 同用户同柜 10 分钟去重（Redis 键，近重返回既有单号）→
  自动建工单（severity 映射、device_no=柜号）；管理端零改动（详情展示 source/报障人）；
- 不变量⑭（**报障可回溯**：USER_REPORT 工单必有 reporter_user_id 且工单日志完整——替换原"数量恒等"同义反复项）。

### D2 欠费闭环
- `arrears_record`：id/user_id/order_id(唯一)/amount_fen/settled_fen/status(1 OPEN/2 SETTLED)/
  create_time/settle_time；KEY(user_id,status)；
- 产生：`BillingService.chargeOverdue` 不足额 → 同事务落/累加欠费单（替代仅告警）；
- 用户端：`GET /user/arrears` + `POST /user/arrears/{id}/pay`（余额 CAS → 结清；不足拒绝）；
- 管理端：`GET /admin/arrears`（read）+ `POST /admin/arrears/{id}/waive`（减免核销，SUPPORT/SUPER，
  审计+备注——审查建议的客诉闭环）；
- 下单门槛：`SwapOrderService.create` OPEN 欠费 → TAKE/SWAP 拒绝、RETURN 放行；
- 告警联动：结清/减免后 `markRecovered(ORDER_ARREARS)`；
- 不变量⑬（欠费守恒：OPEN 合计 = Σ(超时费应收-实收) 时间窗内）。
- **补缴入分账**（与 B 联动的关键口径）：欠费补缴是对原订单的增量收入 → 生成分账流水补行
  （见 B2 event_type=ARREARS_SETTLE），避免"收了钱不结算"。

### D3 优惠券（发→锁→核销，含 4 条释放路径）
- `coupon_template`：id/name/type(1 FIXED 立减分)/value_fen/min_amount_fen/total_quantity/
  issued_count/per_user_limit/valid_from/valid_to/status/create_time；**发放时 issued_count CAS 扣减**；
- `user_coupon`：id/user_id/template_id/status(**1 UNUSED/2 LOCKED/3 USED/4 EXPIRED**)/locked_order_id/
  used_order_id/received_time/locked_time/used_time/expire_time；KEY(user_id,status)；
- **适用范围（审查修正）**：仅**余额计费单**（create 时校验无可用套餐，文案明确）；RETURN 禁券；
- 时点：下单校验（归属/UNUSED/有效期/门槛）→ CAS UNUSED→LOCKED；计费完成 CAS LOCKED→USED（核销，
  `discount=min(value, baseFee)`，`order.discount_fen` 记录，`payment_record` 增 `COUPON_DEDUCT`=补贴流水）；
- **释放路径（审查修正，全 4 条终态 + reset）**：① 用户取消；② 超时关闭（延迟任务/扫描）；
  ③ 发令失败补偿 CAS（`sendOpenCommand` 直转 CANCELLED）；④ 异常终止（柜故障/证据丢失/超期转人工）；
  统一收敛为"订单终态钩子"实现，参数化单测覆盖 4 路径；DevResetService 全量复位；
- **到期**：惰性（校验视过期置 EXPIRED）+ 日报口径声明；
- **退款与券**（拍板项）：v1 声明"券核销后不退"（一次性权益），退款冲正按实收（B2）；
- 不变量：券状态机守恒（LOCKED 必有活跃单；USED 必有完成单）。
- **COUPON_DEDUCT 与对账③联动（审查发现）**：`ReconcileService` 收费类型白名单增 `COUPON_DEDUCT`
  （防全额券单零流水被误报"完成无支付"）。

### D4 站内信（低成本补全"服务"触达，审查建议）
- `user_message`：id/user_id/type(RECHARGE/ARREARS/REFUND/COUPON/WORK_ORDER)/title/content/read_flag/
  create_time；KEY(user_id, read_flag, id)；
- 写点（4 处）：券发放、欠费产生、退款到账、报障工单关闭；读端点 `GET /user/messages` +
  `POST /user/messages/{id}/read`；短信/微信推送明确不做（声明）。

## 六、WP-B：代理/站点分润结算（资金域大块，最后落地）

### B1 模型（db/12）
- `agent`：id/agent_no(唯一)/name/contact/status/**share_bp**(0~10000 万分比)/settlement_cycle(记录口径)/
  create/update；
- `station` 增列 `agent_id BIGINT NULL`（NULL=直营）；
- **`order_settlement` 改为 append-only 资金流水**（审查修正，非"每单一行终态"）：
  id / order_id / order_no / station_id / agent_id(可空) / **event_type(ORDER / REFUND_REVERSAL /
  ARREARS_SETTLE)** / base_type(CASH/PLAN_TIMES/PLAN_MONTHLY) / base_amount_fen / agent_share_fen /
  platform_share_fen / statement_id(可空) / create_time；**UNIQUE(order_id, event_type)**；
  KEY(agent_id, statement_id, create_time)；
- `settlement_statement`：statement_no(唯一)/agent_id/period_start/period_end/order_count/
  base_amount_fen/agent_amount_fen/platform_amount_fen/**subsidy_fen(券补贴列，审查建议)**/
  status(1 GENERATED/2 CONFIRMED/3 PAID)/generated_by/confirmed_by/paid_by 及时间/remark/create/update；
  UNIQUE(agent_id, period_start, period_end)。

### B2 口径（拍板项，文档显式声明）
- **基数**：CASH 单=`fee_fen`（实收）+ 券抵扣（平台补贴）；次卡单=`floor(price/total_times)`；
  月卡单 v1=0（仅计 order_count，声明"套餐池分成待协议化"）；**退款冲正**=按原单基数负向
  （REFUND_REVERSAL，负行）；**欠费补缴**=ARREARS_SETTLE 正行（补缴额）；
- **分配**：`agent_share = base × share_bp / 10000`（**long 运算**，floor）+ `platform = base - agent`
  （不丢分）；share_bp 0/10000 合法（0=全平台，10000=全代理）；**券 100% 抵扣 + 高分成时
  agent_share > 实收 → 差额记 statement.subsidy_fen（平台补贴列），不封顶截断**；
- **挂钩点（审查修正）**：统一在 `BillingService.charge` 末尾（TAKE/SWAP/RETURN 三条完成路径唯一汇聚点，
  与计费同事务）；退款成功（RefundService.apply）同事务写 REFUND_REVERSAL。
- **结算单语义（审查修正）**：顺序批——`agent_id=? AND statement_id IS NULL AND create_time<=生成时刻`；
  回填 `statement_id` 用条件 UPDATE（CAS 防并发生成双 claim）；**PAID 不可变**；迟到/冲正/补缴流水
  自然进下一期；**直营流水（agent_id NULL）不参与生成**，但纳入对账⑩的守恒口径。
- 对账不变量：**⑩a 分账守恒**（Σ(agent_share+platform_share) = Σbase，含负行）；
  **⑩b 结算挂单一致**（挂单流水合计 = 结算单金额；无孤儿挂单）；**⑩c 完成单必有 ORDER 流水**（时间窗内）——
  **DevResetService 语义**：reset **不删** order_settlement（保留历史完成单流水，⑩c 不误报），
  仅清 settlement_statement 并把已挂单流水 `statement_id` 置 NULL（释放挂单，复跑 generate 不撞唯一键）。

### B3 报表
- `GET /admin/report/station`（`admin:report:read`）：按站点/代理聚合周期内 订单数/基数/平台留存/
  代理分成/补贴（直营与代理两视角）——复用 DashboardService 的聚合风格（读路径、无缓存起步）。

## 七、联调闭环与迁移

- **迁移**：db/11（RBAC+退款加列）→ db/12（结算）→ db/13（对账）→ db/14（用户服务）；
  全部 information_schema 幂等守卫（含 db/14 的 **COLUMNS 守卫 ALTER** 与 db/11 退款加列）；
- **审查要求的迁移纪律**：本地全量库**连续应用两遍**断言幂等；**上云前 myqldump 备份**
  （已有每日备份，另行手动快照）；按 WP 独立执行独立验证（11→12→13→14 各随 WP 提交）；
  **无 down 脚本——回退=恢复快照**（写入迁移手册，声明）；
- **DevSeeder 扩展**（幂等）：管理员 admin（密码 `SWAP_ADMIN_BOOTSTRAP_PASSWORD` env）/
  **新增 2 个站点**（各挂一个柜，分别归属 2 个代理商；ST-001 保持直营）/
  1 张券模板 + 给用户 1-3 发券；
- **DevResetService 扩展**（幂等复跑，审查修正版）：订单终态钩子释放券；`user_coupon` 清理并回算
  `issued_count`；清 arrears / channel_bill / recon_diff / user_message（联调语义）；
  settlement_statement 清空 + 流水解挂（见 B2）；admin_user 保留；
- **开关**：新域无独立开关；dev 专属（账单导出、种子）挂 `swap.dev.enabled`。

## 九、取舍与明确不做（声明）

- 不做：多城市/多租户、发票、保险、车辆管理、短信/微信推送（站内信替代）、前端与动态菜单、
  数据权限（站点过滤）、结算打款真实通道（PAID 仅状态与留痕）、券核销后退还（v1 声明不退）；
- 简化：月卡分账基数=0（协议化留后）；渠道账单本地生成（真实渠道替换 import 实现）；
  券仅立减型；到期惰性处理；渠道对账暂不含退款通道侧（MOCK 边界声明）。

## 十、风险与对策

| 风险 | 对策 |
|---|---|
| Spring Security 影响既有行为 | securityMatcher 收敛；旧过滤器退役（含测试迁移）；403 处理链补全；batch1-8 全量回归 |
| break-glass 权限面 | 显式 SUPER + bootstrap 审计 + 轮换文档；独立限流 |
| 分账/退款/欠费资金错账 | append-only+冲正模型；debit=credit 守恒断言；⑩abc；WP-0 先行 |
| 券并发/漏释放 | LOCKED 中间态 + 全 CAS + 终态统一钩子 + 4 路径参数化测试 |
| 迁移风险 | 双遍演练 + 快照备份 + 无 down（恢复快照）声明 |
| 范围蔓延 | 每 WP 独立交付可回滚；WP-0/A 先行不影响既有交付面 |
