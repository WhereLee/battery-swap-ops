## 1. Cabinet 柜

| 状态 | 含义 | 进入条件 | 离开 |
|---|---|---|---|
| ONLINE 在线 | 心跳 TTL 内 | 心跳到达 | 心跳超时 → OFFLINE；人工 → MAINTENANCE/DISABLED |
| OFFLINE 离线 | 心跳 TTL 过期 | 心跳超时 | 心跳恢复 → ONLINE |
| MAINTENANCE 维护 | 人工下线检修 | 人工 | 人工恢复 → ONLINE |
| DISABLED 停用 | 人工停用（计划退役） | 人工 | 人工启用 → ONLINE |

- 判活 = Redis online key TTL（沿用范例）；心跳仅做对账，不改业务状态；
- 预占/开仓**不因柜离线而回滚**——按超时释放（§4）。

## 2. Cell 仓

物理状态：

| 状态 | 含义 | 进入（事件） | 离开（事件） |
|---|---|---|---|
| EMPTY 空闲 | 无电池、可用 | `DOOR_CLOSED`（取出后关仓）/ 初始 | `BATTERY_IN` → OCCUPIED |
| OCCUPIED 占用 | 有电池 | `BATTERY_IN` | `BATTERY_OUT` → EMPTY |
| FAULT 故障 | 门锁/传感器异常 | `CELL_FAULT` | 人工修复 → EMPTY（按实况）|
| DISABLED 停用 | 人工停用 | 人工 | 人工启用 → EMPTY |

锁定（非状态，字段 `lock_order_id` + 预占 TTL）：

- 分配时条件 UPDATE：`lock_order_id = ? WHERE cell_id=? AND lock_order_id IS NULL AND status='OCCUPIED'`；
- 开仓完成 / 订单终态 / 超时释放 → 清空 `lock_order_id`；
- 锁定不参与物理状态，避免"预占态"污染设备语义。

## 3. Battery 电池

| 状态 | 含义 | 进入（事件） | 离开（事件） |
|---|---|---|---|
| CHARGING 充电中 | 在仓，soc < 阈值 | `BATTERY_IN`（归还/初始） | soc ≥ 阈值（`SOC_REPORT`）→ FULL；人工 → REPAIR/RETIRED |
| FULL 满电待换 | 在仓，可被分配 | `SOC_REPORT` 达阈值 | `BATTERY_OUT` → LOANED；人工 → REPAIR/RETIRED |
| LOANED 借出 | 在用户手中（holderUserId 非空） | `BATTERY_OUT`（订单驱动） | `BATTERY_IN` → CHARGING（还回） |
| REPAIR 维修 | 人工送修 | 人工/健康判定 | 修复归仓（`BATTERY_IN`）→ CHARGING |
| RETIRED 退役 | 寿命终止 | 人工 | 无（终态） |

- 满电阈值 soc ≥ 90（可配）；阈值判定由设备上报时执行（`SOC_REPORT`）；
- **位置与状态一致性**：CHARGING/FULL ⇒ cellId 非空、holderUserId 空；LOANED ⇒ 反之（DB 唯一约束，S0.5）。

## 4. SwapOrder 订单

### 4.1 订单类型（S0.1 §4 的细化）

| 类型 | 场景 | 动作 |
|---|---|---|
| SWAP 换电 | 用户在持一块电池 | 取满电 + 还亏电（同一仓） |
| TAKE 首借 | 用户未在持电池 | 只取满电 |
| RETURN 退租 | 用户结束服务 | 只还电池（分配空仓） |

> 用户"至多持一块电池"由 `battery.holder_user_id` 唯一约束保证。

### 4.2 主状态机（共骨架）

| 状态 | 含义 | 进入 | 离开 |
|---|---|---|---|
| PENDING_OPEN 待开仓 | 已分配+预占，指令在途 | 下单成功 | `DOOR_OPENED`→OPENED；超时/取消→CANCELLED / TIMEOUT_CLOSED |
| OPENED 已开仓 | 门开，等取（RETURN 等还） | `DOOR_OPENED` | 取电事件→（TAKE）COMPLETED /（SWAP）TAKEN；（RETURN）`BATTERY_IN`→COMPLETED；超时→TIMEOUT_CLOSED |
| TAKEN 已取待还 | SWAP：满电已取，等还亏电 | `BATTERY_OUT` | `BATTERY_IN`（亏电入仓）→COMPLETED；超时→OVERDUE |
| OVERDUE 逾期占用 | 借出超时未还（可继续归还） | `TAKEN` 超时（默认 24h） | `BATTERY_IN`→COMPLETED（含超时费）；人工→EXCEPTION |
| COMPLETED 完成 | 业务闭环（终态） | 完成事件 | — |
| CANCELLED 取消 | 用户/系统取消（未取电） | 用户取消 / 开仓失败 | — |
| TIMEOUT_CLOSED 超时关闭 | 未开仓/未取电超时（终态） | 超时任务 | — |
| EXCEPTION 异常 | 事件不匹配/设备异常，人工介入 | 对账异常 / 人工 | 人工处置（补记/退款）→COMPLETED |

（状态数 8；"6 套状态机"按载体计，订单含终态旁路。）

### 4.3 事件 → 迁移（订单视角）

| 事件 | 订单条件 | 迁移与动作 |
|---|---|---|
| `DOOR_OPENED(cellNo)` | PENDING_OPEN 且 cell 匹配 | → OPENED；指令销账 ARRIVED |
| `BATTERY_OUT(batteryNo)` | OPENED 且 battery = takeBattery | TAKE → COMPLETED（电池 LOANED；扣次/计费）；SWAP → TAKEN |
| `BATTERY_IN(batteryNo)` | OPENED（RETURN）或 TAKEN（SWAP） | RETURN/SWAP → COMPLETED（电池归仓 CHARGING；扣次/计费） |
| `DOOR_CLOSED` | 信息性（用于审计/对账） | 不单独推进（完成以电池事件为准） |
| `CELL_FAULT/BATTERY_FAULT` | 订单活跃且对象匹配 | → EXCEPTION（人工；必要时换仓/退款） |
| 开仓指令 SEND_FAILED | PENDING_OPEN | 重试分层（S3）；超限 → CANCELLED + 告警 |
| 预占/开仓/取电超时 | 各状态 | 释放预占 → TIMEOUT_CLOSED |
| TAKEN 超时（未还） | TAKEN | → OVERDUE（告警 + 超时费口径） |

### 4.4 计费触发点

| 类型 | 触发 | 动作（幂等，PaymentRecord 唯一键） |
|---|---|---|
| SWAP | 还电入仓事件（COMPLETED） | 套餐扣次 / 余额扣费 |
| TAKE | 取电事件（COMPLETED） | 套餐扣次 / 押金校验 |
| RETURN | 还电入仓事件（COMPLETED） | 押金退还（模拟） |
| OVERDUE→COMPLETED | 归还时 | 套餐扣次 + 超时费 |

## 5. TransferTask 调拨（P2）

| 状态 | 含义 | 迁移 |
|---|---|---|
| PENDING 待执行 | 系统生成（供需失衡） | 人工/系统受理 → IN_PROGRESS；取消 → CANCELLED |
| IN_PROGRESS 执行中 | 已受理，装运电池 | 完成 → COMPLETED；异常 → CANCELLED |
| COMPLETED 完成 | 电池到达目标站点入库 | — |
| CANCELLED 取消 | 人工取消 | — |

## 6. WorkOrder 工单（P2）

| 状态 | 含义 | 迁移 |
|---|---|---|
| PENDING_ASSIGN 待指派 | 告警生成工单 | 指派 → PROCESSING |
| PROCESSING 处理中 | 运维接单 | 提交 → PENDING_ACCEPT |
| PENDING_ACCEPT 待验收 | 处理完成待确认 | 验收 → CLOSED；驳回 → PROCESSING |
| CLOSED 关闭 | 终态 | — |
| CANCELLED 取消 | 误报作废 | — |
