## 1. 拓扑与端点

| 方向 | 通道 | 端点 | 说明 |
|---|---|---|---|
| 上行心跳 | HTTP（恒） | `POST /api/device/heartbeat` | 判活（Redis TTL），携带柜状态 |
| 上行事件 | HTTP（S1）/ MQ `swap-device-event`（S3） | `POST /api/device/event` / topic `swap-device-event` | 状态变化（唯一事实源） |
| 下行指令 | HTTP（同步应答） | `POST /cmd`（设备侧） | 开仓等动作，同步回执 |
| 下行查询 | HTTP（同步应答） | `POST /cmd/query`（设备侧） | 实况快照（对账用，S3） |

## 2. 报文定义

### 2.1 心跳（上行）
```json
{ "cabinetNo": "SWAP-C-001", "status": 1, "bootId": "a1b2...", "eventSeq": 42 }
```
- `status`：1 在线可用 / 2 满载（无空仓可还）/ 3 故障 / 4 维护（可选上报，P0 用 1/3）；
- 心跳**不参与事件序守卫**（自述对账信号，沿用范例语义）；`bootId/eventSeq` 可选携带，用于对账参考。

### 2.2 事件（上行）
```json
{
  "cabinetNo": "SWAP-C-001",
  "eventType": "BATTERY_OUT",
  "cellNo": 3,
  "batteryNo": "BAT-000123",
  "soc": null,
  "bootId": "a1b2...",
  "eventSeq": 43,
  "commandSeq": 7
}
```
- `eventType` 目录（§3）；`commandSeq` 可空（非指令驱动事件为空）；
- 必填：`cabinetNo/eventType/bootId/eventSeq`（`cellNo/batteryNo/soc` 按事件类型要求）。

### 2.3 开仓指令（下行）
```json
{ "cabinetNo": "SWAP-C-001", "cellNo": 3, "commandSeq": 7 }
```
回执：`{"code":0,"msg":"已受理"}`（含 seq 幂等忽略）；`{"code":1,"msg":"拒绝原因"}`。

### 2.4 状态查询（下行，S3）
```json
{ "cabinetNo": "SWAP-C-001" }
```
应答：`{"code":0,"data":{"cabinetNo":"...","cellStates":[{"cellNo":3,"status":2,"batteryNo":"...","soc":88}],"bootId":"...","eventSeq":43,"lastCommandSeq":7}}`

## 3. 事件目录（v1）

| eventType | 触发 | 必填字段 | 语义 |
|---|---|---|---|
| `DOOR_OPENED` | 开仓指令执行/手动开门 | cabinetNo, cellNo, commandSeq? | 门已开（指令销账锚点） |
| `BATTERY_OUT` | 电池被取出 | cabinetNo, cellNo, batteryNo | 取电（FULL→LOANED 依据） |
| `BATTERY_IN` | 电池被放入 | cabinetNo, cellNo, batteryNo | 还电（归仓充电依据） |
| `DOOR_CLOSED` | 门关闭 | cabinetNo, cellNo | 审计/对账（不单独推进订单） |
| `SOC_REPORT` | 充电中电量上报（周期或变化上报） | cabinetNo, cellNo, batteryNo, soc | 满电判定（≥90）与健康跟踪 |
| `CELL_FAULT` | 仓位故障（门锁/传感器） | cabinetNo, cellNo | 告警；订单异常判定 |
| `CABINET_FAULT` | 柜级故障 | cabinetNo | 告警；整柜跳过分配 |

## 4. 安全与签名

- 每设备（柜）独立密钥（32hex，仓库零明文；登记时生成/导入，仿真环境走本地密钥文件）；
- `X-Device-No`（cabinetNo）+ `X-Device-Sign`（HMAC-SHA256 hex）；常量时间比对；
- canonical（null → 空串，字段序固定）：

| 消息 | canonical |
|---|---|
| 事件 | `cabinetNo\|eventType\|cellNo\|batteryNo\|bootId\|eventSeq` |
| 心跳 | `cabinetNo\|status` |
| 指令 | `cabinetNo\|cellNo\|commandSeq` |

- 错误语义：验签失败 401；协议垃圾（缺必填/类型错）400；设备侧拒绝走 `code=1`（业务码）；
- 链路跟踪：`X-Trace-Id`（HTTP）/ `traceId`（MQ property，S3），全链路沿用。

## 5. 可靠性与幂等（协议级）

| 机制 | 说明 |
|---|---|
| 事件序守卫 | `(bootId,eventSeq)` 单调；同代际旧序/重放拒绝（幂等丢弃）；**跨代际重放拒绝（S3.1 已落地：已见代际集合 `swap:boot-current/history`，历史命中=旧代际重放；Redis 异常 fail-open）** |
| 指令 seq | `commandSeq` 柜内单调（Redis INCR）；柜侧 `seq<=lastSeq` 幂等忽略；**曾被拒 seq 重试明确拒绝**（双线） |
| 销账 | 事件携 `commandSeq` 时按 (cabinetNo,seq) 精确销账指令流水（证据驱动） |
| 会话关联（S2 落地） | 同一次开门会话内的 `BATTERY_OUT/BATTERY_IN` 回带该次 `OPEN_CELL` 的 `commandSeq`（柜侧会话保鲜窗 5 分钟）——设备无需知道 orderId，订单域据此精确推进 |
| 保序 | 事件通道单队列保序（S3 MQ 单队列；HTTP 期由柜侧单线程上报保证） |
| 断连补偿 | 柜侧事件本地队列 + 重连补传（S3 语义；协议允许迟到事件，由序守卫吸收） |

## 6. 契约钉合（双端一致性测试）

- 双端各自实现 canonical/HMAC（server 与 sim 互不依赖），用**同一组固定向量**验证：
  - `签名(HMAC, canonical)` 固定输入输出（含 null 字段、中文、边界）；
  - 枚举码值一致（eventType/batteryStatus/cellStatus/柜 status）；
- 契约测试在两端各自运行（CI 双端红灯机制），不共享 jar（沿用范例"双端钉合"模式）。

| 设计点 | 参考 | 取舍 |
|---|---|---|

## 8. S3 增补（已落地，2026-09-11）

### 8.1 MQ 适配层（§7 同构范例 PROTOCOL-V2）

- **topic/消费组**：`swap-device-event`（1 队列保序）/ 平台消费组 `platform-device-event`；告警上行 `swap-alarm`（1 队列，Agent 接缝）。
- **信封**：body = 与 HTTP 完全相同的事件 JSON（cabinetNo/eventType/cellNo/batteryNo/soc/commandSeq/bootId/eventSeq）；
  柜号/签名/traceId 置 message property：`X-Device-No` / `X-Device-Sign`（canonical 拼法与 HTTP 同一实现）/ `traceId`；keys=`{cabinetNo}-{eventSeq}`。
- **保序**：sim 单发送线程 + 有界队列；失败事件**队首持留**（不跳过重排），快速退避 1~5s ×5 → 5s 节拍等 broker 恢复；队列满丢最旧（QUERY_STATE/对账兜底）。
- **平台消费**：并发度=1（SimpleConsumer 单线程 receive→处理→ack）；验签复用 `DeviceChannelAuthenticator`、编排复用 `DeviceEventService`。
- **失败分级**：验签失败/未登记/协议垃圾/信封不一致 = 毒消息 **ack 丢弃**；瞬时异常**不 ack** 等 broker 重投（耗尽进 `%DLQ%platform-device-event`）；重复投递由业务幂等吸收。
- **通道降级**：`swap.sim.event-channel=http|mq|dual`（fail-fast 校验），心跳恒 HTTP（判活不依赖 broker）。

### 8.2 状态查询与对账（S3.2）

- `POST /cmd/query`：canonical 固定 `cabinetNo|QUERY|0`（查询不占指令 seq）；返回 state/cells/bootId/eventSeq/lastCommandSeq。
- 平台 `MonitorReconcileTask`：超时 PENDING → 查询 → 事件丢失按证据销账（门开→OPENED；电池已取但事件缺失→EXCEPTION 交人工）；未执行同 seq 重试（幂等），超限 RETRY_EXCEEDED 转人工。

### 8.3 跨代际重放拒绝（S3.1）

- 平台维护 `swap:boot-history:{cabinetNo}`（已见代际集合，TTL 30 天）：bootId 为历史代际的事件在序守卫**之前**拒绝；同代际乱序/重复由 DB 序守卫兜底。

### 8.4 充电策略下发（S4.3）

- 动作：`SET_CHARGE_POLICY`（柜级，不占 cellNo）；报文体：
  `{action, cabinetNo, commandSeq, policy:{version, priority, windows:[{startHour,endHour,powerLimitW,feeFenPerKwh}]}}`；
- 签名 canonical：`cabinetNo|POLICY|version|commandSeq`（**策略版本纳入签名**，载荷不可篡改）；
- 版本单调：新版本应用 / 同版本幂等忽略 / 旧版本拒绝；窗口必须连续覆盖 0~24；
- `feeFenPerKwh` 仅平台计费用（柜端只执行功率上限）；
- 回执：`code=0 + data.appliedVersion`（联调为同步应用；真实柜异步确认走后续事件扩展）。
