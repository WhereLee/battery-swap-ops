## 〇、恢复锚点（每次开工先看这节）

- **仓库**：`battery-swap-ops`（remote `WhereLee/battery-swap-ops`）；每步 `mvn -B -ntp clean test` 全绿 → commit → push → `gh run watch <id> --exit-status`。
- **本地环境**：MySQL 3306 / Redis 6379（F:\Redis）/ MQ 9876+10911+8081 常驻；
  server/sim 按需启动：`.local\run-server-fast.bat`（fast 参数：SLA=0、心跳 5s 等）、`.local\run-sim-dual.bat`。
- **脚本红线**：`.ps1` 全英文（含字面量）；联调数据用 `POST /dev/device/reset` 复位；MySQL 走 `cmd /c "mysql -uroot -proot swap_ops ..."`。
- **提交序**：B2.1 站点/柜/仓 → B2.2 电池登记 → B2.3 用户管理 → batch5 收口（块记录/README/阶段计划）。
- 停服注意：clean test 前先杀 javaw（jar 锁）；jar 重建后 server 必须重启才生效。

## 一、B2.1 站点/柜/仓 CRUD（第一个提交）

**站点**（字段：stationNo 唯一 / name / address / status 1运营 2停用）
- `POST /admin/station`：stationNo 必填（`^[A-Za-z0-9-]{2,32}$`，唯一）、name 必填 ≤32、address ≤128；status 默认 1。
- `POST /admin/station/{id}`：改 name/address（stationNo 不可变）；status 走既有端点。
- `DELETE /admin/station/{id}`：有柜引用则拒绝。
- 写路径 evict `station:active:list`（status 端点已有；补到 create/update/delete）。

**柜**（字段：cabinetNo 唯一 / stationId / cellCount / status / secret）
- `POST /admin/cabinet`：cabinetNo 必填唯一；stationId 必须存在；cellCount 1~48；secret 必填（32~64 hex，设备侧同值）；
  **自动创建 cellCount 个 EMPTY 仓**；响应中 secret 脱敏（只回 `secretMasked`）。
- `POST /admin/cabinet/{id}`：可改 stationId、secret（轮换）、cellCount：
  - 增加：补建仓；减少：仅当被裁撤的仓"无电池且无锁"时删仓，否则拒绝；
  - 任何变更后 `allocationService.rebuildFromDb()`。
- `DELETE /admin/cabinet/{id}`：存在有电池/有锁的仓则拒绝；否则删仓 + 删柜 + 重建池。
- 状态运维走既有 `POST /admin/cabinet/{cabinetNo}/status`（S2.1）。

**仓**：不单独新增（随柜 cellCount 生命周期）；编辑仅既有维护态端点（S2.1）。文档声明。

**验收**：单测（校验/唯一冲突/缩减拒绝/secret 脱敏/池重建调用）；剧本 `_c10_asset_crud.ps1`
（建站→建柜→仓数正确→改柜（增仓）→建电池放置→删柜被拒（有电池）→清仓后删柜→删站）。

## 二、B2.2 电池登记（第二个提交）

- `POST /admin/battery`：batteryNo 必填唯一（`BAT-` 前缀建议不强校验）、model ≤32、soc/soh 0~100、cycleCount ≥0；
  - 带 cellId：目标仓必须存在且 EMPTY → 置 OCCUPIED + 双向绑定，状态=FULL（soc≥阈值）否则 CHARGING；
  - 不带 cellId：在途（cellId=null，holder=null，status=CHARGING）。
- `POST /admin/battery/{batteryNo}`：改 model/soc/soh/cycle；改位（仅空仓或转在途）；持有人非空拒绝；改位后重建池。
- `DELETE /admin/battery/{batteryNo}`：仅在途且无持有人、未被订单引用（take/return_battery_id）时允许。
- `GET /admin/battery` 分页查询已有（S2.1），复用。
- **验收**：单测（放置/在途/占用仓拒绝/持有人拒绝/订单引用拒绝）；剧本并入 `_c10`。

## 三、B2.3 用户管理（第三个提交）

- `GET /admin/user`：分页（page/limit/phone 模糊）。
- `POST /admin/user/{id}/status?status=1|2`：停用即时生效（`resolve`/login 均校验 status）；
  停用不清 token（token 校验时状态即拒）——文档写明语义。
- **验收**：单测（状态非法拒绝/停用后 resolve 失败——由 UserAccountService 既有校验覆盖）；
  剧本 `_c11_user_admin.ps1`（列表→停用→登录 401/失败→启用→登录成功）。

## 四、收口（batch5）

## 五、边界（不做的）

- 站点/柜/电池的批量导入、Excel 导出：不做（S5 报表阶段再议）；
- 用户管理不做删号/改手机号（实名/合规场景另论）；
- 仓的独立登记 UI/接口：不做（随柜生命周期）。

## 六、风险与规避

1. **建柜不建仓/仓数不一致** → 建柜必须同事务建仓；缩减仓先校验空仓+无锁。
2. **删除破坏引用**（柜/电池/站被订单或告警引用）→ 删除前显式引用检查（宁可拒绝，不级联删）。
3. **secret 泄漏** → 响应一律脱敏；不写日志明文。
4. **池不一致** → 柜/仓/电池任何结构变更后统一 `rebuildFromDb()`（幂等）。
5. **联调数据污染** → `_c10` 结尾清理自建资产；用户测试用 25 号用户。
