> 阶段：S0 设计冻结 · 第 5 小阶段 ｜ 状态：待自查

## 2. 关键约束（不变量落法）

| # | 约束 | 落法 |
|---|---|---|
| C1 | 一块电池至多在一个仓 | `UNIQUE KEY uk_battery_cell (cell_id)`（NULL 可重复 = 不在仓） |
| C2 | 一块电池至多被一个用户持有 | `UNIQUE KEY uk_battery_holder (holder_user_id)`（NULL 可重复 = 未借出） |
| C3 | 一个仓至多一块电池 | C1 反向表达；`cell.battery_id` 仅作展示冗余，写入以 battery 为准（事件驱动同事务） |
| C4 | 一个用户至多一个活跃订单 | MySQL 8 无部分索引——生成列 `active_user_key = IF(status IN ('PENDING_OPEN','OPENED','TAKEN','OVERDUE'), CAST(user_id AS CHAR), NULL)` + `UNIQUE(active_user_key)`（与范例 knowledge 的 generated column 手法同源） |
| C5 | 指令 seq 柜内唯一 | `UNIQUE KEY uk_cabinet_seq (cabinet_no, command_seq)` |
| C6 | 订单号唯一 | `UNIQUE KEY uk_order_no (order_no)` |
| C7 | 计费幂等（同单同类型一次） | **db/18 修订**：原 `UNIQUE KEY uk_order_type (order_id, payment_type)`，但该键对 `REFUND` 一并生效，会把**同一订单的第二笔合法部分退款**吞掉（`refund_record` 的唯一键是 `(order_id, reason)`，不同原因的两笔退款是合法的）。现改为生成列 `idem_key` + `UNIQUE KEY uk_payment_idem (idem_key)`：`REFUND` 与 `order_id IS NULL` 两行为 NULL（唯一索引不约束 NULL），其余仍为 `orderId:paymentType`。`uk_trade_no` 原样保留。详见 `document/block-records/批次35-资金台账两处口径修正.md` |
| C8 | 柜编号唯一 | `UNIQUE KEY uk_cabinet_no (cabinet_no)`；`station_no`、`phone`、`battery_no` 同理 |
| C9 | 柜内仓编号唯一 | `UNIQUE KEY uk_cabinet_cell (cabinet_id, cell_no)` |

## 3. 并发落法（与 S0.1 §6 对应）

| 场景 | 落法 |
|---|---|
| 分配满电电池 + 空闲仓 | Redis Lua（per 柜）：从可分配集合原子取一（cell+battery），写预占键 `swap:preempt:{orderNo}`（TTL=开仓超时）；DB 兜底：`UPDATE cell SET lock_order_id=? WHERE cell_id=? AND lock_order_id IS NULL AND status='OCCUPIED'`（影响行数 0 → 换候选重试） |
| 指令 seq 生成 | Redis `INCR swap:cmd-seq:{cabinetNo}`（原子、跨重启）；启动对齐 `max(Redis, DB MAX)`（LUA）——沿用范例 |
| 订单/电池/仓状态迁移 | 全部条件 UPDATE（from 状态守卫） |
| 归还入仓 | 事件驱动：先条件更新订单（CAS），再写 battery.cell_id + holder 清空；C1/C2 唯一索引兜底并发 |
| 计费 | 先 CAS 订单终态，再插 payment_record（C7 兜底重复） |
| 告警治理 | 去重 SETNX + DB 兜底 + 限速 ZSET（沿用范例） |

## 4. Redis 键族（`swap:` 前缀）

| 键 | 用途 | TTL |
|---|---|---|
| `swap:online:{cabinetNo}` | 在线判定（EXISTS） | 心跳超时（默认 60s） |
| `swap:cmd-seq:{cabinetNo}` | 指令 seq（INCR） | 无 |
| `swap:preempt:{orderNo}` | 预占快照（cell/battery） | 开仓超时（默认 120s） |
| `swap:alloc:{cabinetNo}` | 可分配集合（FULL 电池仓；事件驱动维护） | 无 |
| `swap:alarm-dedup:{no}:{type}` / `swap:alarm-rate:{type}` | 告警去重/限速 | 窗口 |
| `swap:boot-history:{cabinetNo}`（S3） | 跨代际重放守卫 | 30 天 |

## 5. 存储与保留

- 所有时间列 bigint 毫秒（`create_time/update_time` 等，沿用范例 D-H）；
- `command_log`、`alarm`、`device_event_log` 保留 90 天（清理任务 S3，分批 LIMIT）；
- 订单/支付/电池轨迹长期保留（审计）。

## 6. 与参考的取舍

| 设计点 | 参考 | 取舍 |
|---|---|---|
| 表范式（状态机表/条件更新/毫秒/金额分） | 范例 knowledge（conditional-update / state-machine / money-fen） | **直接复用** |
| 活跃订单唯一 | 范例 knowledge 的 generated column 手法 | **采用**（parking 场景曾因跨表约束放弃，本场景单表适用） |
| 实体-属性-时序分离 | ThingsBoard/JetLinks | **裁剪**：无 TSDB；遥测只留最新值（soc/soh） |
| 设备流水 | 范例 device_record/command_log 模式 | **复用** command_log；报文级 log 可选 |
