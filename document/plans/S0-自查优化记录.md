| 4 | S0.2 订单状态数（8）与 S0.1 表述不一致 | S0.2 §4.2 为权威；S0.1 只保留"status 字段"，不展开枚举 |
| 5 | 阶段计划 S1.1 写"父 POM + server + sim + contract + CI 空跑"未定聚合方式 | 决策：**三模块同父聚合**（contract/server/sim），CI 单 job `mvn verify` 跑双端测试；sim 仍可独立启动/独立部署。理由：双端 Boot 版本本就对齐、避免共享契约 jar 的双 job 安装链；sim 独立性靠部署形态而非构建树（与范例"sim 不聚合"的取舍不同，属于本项目的显式选择） |
| 6 | 管理端鉴权未定（RBAC vs 简化） | 决策：P0 管理员静态 token（配置注入、仓库零明文）；RBAC/@SysLog 复用范例模式列为 S4 可选。理由：范例已充分展示 RBAC，本项目时间窗优先业务可靠性；S0.4 §3 已标注 |
| 7 | 坐标/端口/库名未定 | 决策：groupId `com.swapops`；产品端口 server **8400** / sim **8500**（避开范例 8200/8300）；MySQL 库 `swap_ops`；Redis 前缀 `swap:`（DB 用 0，键前缀隔离） |
| 8 | 契约共享方式未定（共享 jar vs 双端各自实现） | 决策：**共享 `swap-contract` 模块**（本仓三模块聚合，双端依赖同一契约类）+ 契约钉合测试。与范例"双端各自实现 + 钉合"不同：范例因 sim 独立仓；本仓同仓聚合，共享模块更少重复。风险：双端编译期绑定加强——用契约测试覆盖语义向量即可 |
| 9 | S0.6 剧本 4 引用"S3 加已见代际加固"与 S0.3 §5 一致 | 保留；S3 设计时展开 |
| 10 | 文档间相对路径引用检查 | S0.2~S0.6 使用 `S0.x-*.md` 相对引用与 `../../项目一-参考基准.md` 外部引用，均可用 |

## 三、S1 开工清单（按阶段计划）

- S1.1 骨架：parent `pom.xml` + 三模块 + `.github/workflows/ci.yml`（`mvn verify`）+ README 初稿；
- S1.2 契约：`swap-contract`（枚举、canonical/HMAC、DTO）+ 双端钉合测试向量；
- S1.3 DB：`db/00-create-database.sql` + `db/01-swap-schema.sql`（S0.5 主体表）+ `db/90-seed-dev.sql`（演示数据）；
- S1.4 台账与心跳：`station/cabinet/cell/battery` 实体与最小服务；心跳入口 + 在线 TTL；
- S1.5 指令-事件闭环：`command_log` seq 幂等/CAS + 事件入口（序守卫雏形）+ 开仓指令下发；
- S1.6 模拟器 MVP：10 柜 × 12 仓注册、单线程事件上报、故障注入（离线/卡门）；
- 门禁剧本 1（S0.6 §2）+ 全量单测绿 + 独立提交推送（新仓库首次 push）→ CI 绿。

## 四、明示风险与后置项

- 管理端 RBAC 缺失（S4 可选）——面试如被问"权限怎么做的"，答"参考范例 RBAC，本项目按业务优先级裁剪"；
- 共享 contract 模块与范例双端独立实现的差异——已在 §一.8 记录理由；
- MQ/MQTT 未接（S3/项目后）——S0.3 §8 已列 S3 增补项；
- 一致性边界：cell.battery_id 为展示冗余，写入以 battery 为准（S0.5 C3）。
