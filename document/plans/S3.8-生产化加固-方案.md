# S3.8 生产化加固——实施方案（S3 收尾）

> 阶段：S3.8（S3 收尾，P1+）｜ 状态：**已确认开工**（2026-09-11）
> 背景：S3.1-S3.7 完成（单测 174/174，batch3 剧本 3/4 全过 + _g6 部分通过）。
> 本阶段把"面试高频 + 生产必备"的并发/一致性/抗压能力做成**标准实现**（非最小演示），
> 明确定义"标准 vs 降级"的差别；D 类（复杂低收益）永久不做。

---

## 一、范围与原则

**做（标准实现）**
1. 缓存：两级（Caffeine L1 + Redis L2）、击穿（单飞）、雪崩（TTL 抖动）、穿透（空值+校验）、一致性（Cache-Aside + Pub/Sub 失效广播 + 延迟双删）
2. 限流：Redis+Lua 令牌桶（原子）、注解 AOP、多维（用户/接口/全局）、429+Retry-After、指标
3. 熔断/隔离：Resilience4j（CircuitBreaker+Bulkhead+TimeLimiter），用于设备下行与外部 HTTP
4. 线程池/连接池：有界池+命名+CallerRuns+指标；Hikari/Tomcat 配比基线；优雅停机
5. ID：Snowflake（workerId 注册、时钟回拨等待/拒绝、可注入时钟），替换全部业务单号
6. 分布式事务标准形态：`outbox_event` 本地消息表 + 中继（DB 为事实源，Redis 仅调度），首批接告警事件
7. MySQL：死锁复现→统一加锁顺序修复→Spring Retry 标准件；间隙锁演示与日志解读
8. Redis 运维：大 key/热 key/慢日志巡检；持久化取舍落档
9. JVM 并发坑位：ABA/DCL/ThreadLocal/SimpleDateFormat/拒绝策略——**测试域可运行演示** + 知识档

**不做（D 类，永久）**
- 自研 Redisson watchdog 续租/fencing（生产用 Redisson，本阶段仅文档说明取舍）
- 2PC/TCC 自研、分库分表、跨机房多活、闰秒/DST 模拟、DNS/Keep-Alive、双进程真部署

**原则**
- 资金/库存/订单状态**不缓存**；缓存只服务展示与看板类读（红线见 §四）。
- 每个 WP：独立 commit（feat/fix/test/docs）→ `mvn clean test` 全绿 → 本地剧本证据 → CI 绿。
- 遇到的问题一问题一文件（`document/pitfalls|fixes|knowledge/`）。

## 二、标准 vs 降级对照（验收口径）

| 能力 | 降级形态（不接受为本阶段交付） | 标准形态（本阶段交付） |
|---|---|---|
| 缓存 | 单层 Redis、过期即回源 | L1+L2、单飞、空值、Pub/Sub 失效、TTL 抖动 |
| 限流 | 计数器 INCR、超发可容忍 | Lua 令牌桶原子、精确不超发、429+Retry-After |
| 熔断 | try/catch 超时、失败继续打 | Resilience4j 状态机 + 指标 + 半开探测 |
| 停机 | kill -9，队列丢事件 | graceful + 调度等待 + sim flush（预算内） |
| ID | 时间戳+UUID（回拨即乱） | Snowflake + 回拨策略 + workerId 唯一 |
| 消息一致性 | 发布失败只 warn（会丢） | outbox 持久化 + 中继补投 + 死信告警 |
| 死锁 | 见了就重启/手工清 | 复现脚本 + 加锁顺序修复 + 标准重试 |
| 资源 | 无界队列/无指标 | 有界池 + 指标 + 快速失败 |

## 四、缓存红线（必须遵守）

- **可缓存**：站点/柜展示信息、套餐目录、看板聚合结果（秒级不一致可接受）。
- **不可缓存**：分配池/仓锁、钱包/押金、订单状态、指令流水、支付单。
- **一致性**：写库成功→删缓存（L2 DEL + L1 Pub/Sub 广播）；读路径 Cache-Aside；
  延迟双删仅用于"删缓存后仍有旧读回填"的窗口，双删间隔 500ms，以 TTL 兜底。
- **降级**：Redis 不可用时读直落 DB（fail-open，只降性能不降正确性）；L1 失效广播丢失靠 TTL。

## 五、风险与声明

1. CI 无 MySQL/Redis 集成环境：DB 死锁、缓存/限流/熔断剧本走**本地证据**（`scripts/verify/batch4`），CI 只跑单测。
2. Resilience4j/缓存改造点均为读路径或展示路径，不动资金/订单写入路径。
3. 新增依赖：caffeine、spring-boot-starter-cache/aop、resilience4j-spring-boot3、spring-retry（版本入 parent dependencyManagement）。
4. 全阶段结束后统一做：**标准 vs 降级取舍自查** + **同步阻塞反思**（见块记录尾部）。
