# S4.2 站间调拨——实施方案（钉口径）

> 状态：开工（2026-09-12）｜ 上游：S4 方案 ｜ 复用：分配池(S2)、延迟队列/告警(S3)、工单(S4.4)、资产 CRUD(S4.5)、对账(S3.5/S4.1)

## 1. 口径与规则（可解释的启发式，不做运筹优化）

- **供需**：按站点统计「满电可换数」（分配池，与看板/分配同源）与「可还仓位数」；
  - 富余站：`full - surplusKeepLevel > 0`（默认 keep=4：本站保留至少 4 颗才可外调）；
  - 缺口站：`deficitTargetLevel - full > 0`（默认 target=3）；
  - 调拨量 = `min(缺口, 富余, maxPerTask)`（默认 maxPerTask=3）。
- **配对**：缺口站按缺口降序，逐个选**最近富余站**（Haversine 经纬度距离；坐标缺失按最大距离排后并如实标注）。
- **明确不做**：路径规划/多跳/成本最优/实时调度（OptaPlanner 类）——文档声明；坐标缺失时不做伪距离。

## 2. 状态机（只前向 + 严格守卫）

```
DRAFT(1) --approve--> APPROVED(2) --首次出库--> EXECUTING(3) --全部入库--> DONE(4)
DRAFT/APPROVED --cancel--> CANCELLED(5)；EXECUTING 不可取消（在途资产必须闭环）
```

- 明细 `transfer_task_item`：每颗电池一行，`PENDING→OUT(在途)→IN(入库)`；任务状态由明细聚合推进（不用人工点"完成"）。
- 出库守卫：电池须在**调出站**的仓内、FULL、无锁 → 落 `out_cell_id`，电池置在途（cellId=null，status=CHARGING 语义"停用待装"，holder=null）；
- 入库守卫：明细则为 OUT、目标仓须属**调入站**且为空 → 落 `in_cell_id`，电池入仓；
- 幂等：item 状态 CAS；重复出/入库请求显式拒绝（不猜）。

## 3. 表（db/07）

- `station` 增 `latitude/longitude`（可空；种子/登记时维护，推荐按距离排序用）；
- `transfer_task`（task_no 唯一、from/to、plan_count、status、created_by/approved_by、时间）；
- `transfer_task_item`（task_no+battery_no 唯一、状态、out_cell_id、in_cell_id、时间）。

## 4. 接口（管理端）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/transfer/recommend` | 调拨建议（配对+数量+距离），只读不落库 |
| POST | `/admin/transfer` | 创建 DRAFT（校验站、数量、富余充足；自动选源站 FULL 电池生成明细） |
| POST | `/admin/transfer/{id}/approve` | DRAFT→APPROVED |
| POST | `/admin/transfer/{id}/items/{batteryNo}/out` | 出库（守卫+明细 OUT） |
| POST | `/admin/transfer/{id}/items/{batteryNo}/in?cellId=` | 入库（守卫+明细 IN） |
| POST | `/admin/transfer/{id}/cancel` | DRAFT/APPROVED→CANCELLED |
| GET | `/admin/transfer` / `/{id}` | 列表/详情（含明细） |

## 5. 对账不变量 ⑧（transfer-ledger）

对非取消任务逐项校验：`OUT 未 IN` 的电池必须**不在仓且无持有人**；`IN` 的电池必须**身处记录的 in_cell_id**；
任务状态与明细聚合一致（如 EXECUTING 必有 OUT、DONE 必全 IN）。差异=人工绕流程改数 → 告警。

## 7. 边界（如实声明）

- 执行方式=**人工确认台账**（管理员点出库/入库）；真实"设备事件驱动调拨"待协议支持调拨动作（roadmap）；
- 电池在途状态复用 `CHARGING + cellId=null`（未在契约新增 TRANSIT 状态码；文档声明语义）；
- 无调拨审批流（单级 approve）、无跨站运力/时间窗。
