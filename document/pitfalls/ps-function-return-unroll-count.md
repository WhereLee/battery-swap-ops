# 坑位：PowerShell 函数返回值展开：`.Count` 的 0/1/N 三态（假 FAIL 与假 PASS 之源）

> 状态：已收敛（2026-09-16，批次21 `_c26` 剧本开发中连续踩中两轮；批次22 `_c27` 换包装后再现）| 环境：Windows PowerShell 5.1

## 现象（同一断言两种抖动）

验证剧本中用 `(OfflineAlarms).Count` 判断"离线告警列表是否为空/非空"，出现**交替的假 FAIL / 假 PASS**：

- 第一轮：隔离轮"告警已入库"断言在**恰好 1 条命中**时**假 FAIL**（等了 150s 超时，日志却证明告警早就在库里）；
- 换一种写法后第二轮：变成"检出"**恒真**（0 条也 PASS）、"清空"**恒假**（0 条也 FAIL）——**方向相反的第二层假象**。

## 根因：PS 函数输出流"单元素数组展开"

函数 `return $items`（$items 是数组）时，输出流按**元素个数**分三态：

| $items 元素数 | 调用方 `$oa = fn` 得到 | `$oa.Count` | `@($oa).Count` |
|---|---|---|---|
| 0 | `$null` | 0（空） | 0 |
| **1** | **标量对象**（PSCustomObject，无 Count 属性） | **`$null`**（→ `-gt 0` 为 false，`-eq 0` 也为 false！） | **1** |
| N | Object[] | N | N |

`$null -gt 0` 和 `$null -eq 0` **都是 false**——断言在"恰好 1 条"时**既不成立也不反成立**，表现为静默失效。

## 两轮错误修复（都别学）

1. ❌ 不包装直接 `(fn).Count`——1 条命中时静默 false（原始 bug）；
2. ❌ `return , $items` + 调用处 `@()` **双保险**——逗号让输出恒为"1 个对象（数组）"，`@()` 把"1 个对象"收集为 1 元素数组 → **Count 恒 1**（无论内部几条）→ 另一方向的假象。

## 正确写法（三态实验实测）

```powershell
function OfflineAlarms { $items = @(... | Where-Object { ... }); return $items }   # 普通 return
@(OfflineAlarms).Count   # 0→0、1→1、N→N ✓
```

即：**函数普通 return 集合 + 调用处 `@(fn)` 包装**。`@()` 收集的是输出流（0 个对象→0、1 个标量→1、N 个对象→N），恰好修复三态差异。

## 可复用教训

- **PowerShell 里"统计函数返回的集合元素数"，一律 `@(fn).Count`**——这是语义修正而非风格洁癖；
- `return , $items` 只用于"把数组作为单个对象交出去"（如嵌套数组语义），**与 `@()` 同用会互反**；
- 剧本/脚本断言出现"特定数据量才复现的假 FAIL"或"恒真/恒假"时，先写**最小三态实验**（0/1/N）复现语义，再改剧本——不要靠跑全流程猜；
- **最大的教训：不要基于失效断言的观测去推导系统行为**——本次一度形成"sim 重启慢（2.7 分钟才心跳）"的错误假设，事后实测 sim 重启 4s 级、系统侧日志无异常，该假设完全来自 `.Count` 假象并已放弃。排障时先证断言自身可信，再证系统。

## 复现②（批次22 `_c27`，换了一层包装又踩）

批次21 的教训是"函数普通 return + 调用处 `@(fn).Count`"，本批写新剧本时却写了一个"自作聪明"的包装函数
`function Arr($x) { return @($x) }`，企图让调用方直接拿到数组——**函数的 `return` 依旧按输出流元素个数展开**：

- 单元素时 `Arr` 返回**裸标量 PSCustomObject**（`array.Count` 语义丧失）→ 断言 `$list.Count -eq 1` 假 FAIL；
- 而同一剧本里多元素列表（仓/电池/订单）全 PASS——**"只有恰好 1 条时假 FAIL"的经典指纹**。

修复：删除 `Arr` 包装，**全部调用处显式 `@(...)`**，并加注释钉住纪律。教训：`@()` 必须在**调用处**；
任何"帮你返回数组"的 PS 函数都是反模式（输出流展开是语言级行为，包装函数无法取消它）。
