# 坑位：把视觉模型当判定者（假阳性模式与正确用法）

> 发现：批次38 ｜ 影响面：任何"用多模态模型做界面评审"的流程
> 一句话：视觉模型是**疑点生成器**，不是判定者——它报的定量主张必须回落到 DOM 测量；
> 它对**小字号**的判断不可采信，对**结构缺失**的判断有提示价值。

## 通道与调用方式（实测）

| 项 | 结论 |
|---|---|
| 模型 | `deepseek-v4-flash-vision-exp`（`input: [text, image]`），经 provider `opencode-go` |
| 调用 | workflow 脚本里 `agent(prompt, { provider: 'opencode-go', model: 'deepseek-v4-flash-vision-exp' })` |
| 读图 | 通过 `read_image` 工具打开绝对路径；prompt 里给出路径即可 |
| **schema 不兼容** | **强制 JSON schema ⇒ 11/11 全失败（返回 null）；同一提示词去掉 schema ⇒ 11/11 成功**。该模型走"自然语言作答"，不产出可被 schema 校验的结构体。要么纯文本行格式自行解析，要么用文本模型做二次汇总 |
| 成本控制 | 一图一 agent、并要求"最多 N 行"输出；11 张图 ≈ 11 个短回答，上下文可控 |

## 假阳性模式（本条是重点）

| 模式 | 实例 | 判定它的量 |
|---|---|---|
| **把"读不出"说成"没渲染"** | "标签列渲染成空白方块/没有文字" | 逐标签测前景/背景对比度：`#67c23a`/`#f0f9eb`=2.08:1 等（**结论方向对、归因错**——不是没渲染，是对比度不可读） |
| **把截图里缺内容说成页面被折叠截断** | "分账流水在第 12 行被截断" | 量滚动容器（`main.el-main:840<2049`）⇒ **这次它是对的**，是我的整页截图只截了一屏（见 `fullpage-capture-inside-scroller.md`） |
| **相邻列串读** | "类型列是数字（8,8,8,7…）" | DOM 采样同一列标签文本：`归还/取电/已完成`（它读的是相邻的"用户"列） |
| **凭视觉宣称几何错位** | "表头整体左移一列，可退金额的单元格跑到退款通道表头下" | 逐列比较表头盒与首行表体盒：89 列 `deltaLeft=0`、`headerTextClipped=false`。**`fixed="right"` 列用 `position:sticky` 绘制，在整页截图里天然显得错位** |
| **对同一张图前后矛盾** | 第一轮说"表头错位"，第二轮（修复后的截图）说"表头与各列对齐，无偏移" | 两轮都别信，只看 DOM |

## 假阴性（它看不见的真问题）

- **12px 数字从不显示**：SOC 列 12 行"可见为空、DOM 文本 0、子元素 10"——
  是 `el-progress` 设了 `status` 就用**图标替换百分比文字**。视觉模型多轮都没提这条，
  DOM 度量一次就捞出来了。
- 12px 灰色页脚说明（"守恒校验只做展示层断言…"）它明确说读不全。

## 正确用法（本次采用的流程）

1. **视觉模型找工作面**：让它描述页面结构、找"看起来不对"的地方（它能准确数行数、读表头、识别空面板）；
2. **所有定量主张回落到 DOM**：对比度、裁切、溢出、错位、列是否有可见文字，逐项写成探针判据；
3. **把它的抱怨变成判据**：本次新增的两条门禁（表头/表体错位、表头文字截断）就是因为它的抱怨**当时无法被证伪**；
4. **它不可信的部分要在文档里写清楚**（本文），否则下一轮又会拿它的结论当事实；
5. **不要为它放宽阈值**：对比度门禁本次从 3:1 **提高**到 4.5:1（WCAG 1.4.3 对 12px 正常字号的要求），
   而不是为了"看起来达标"而调低标准。

## 通用规则

- 模型输出的**数字**一律视为待验证假设；模型输出的**位置**（"我看不清这里"）是有价值的线索；
- 评审清单里同时存在真缺陷与假阳性是常态（本批 3 条几何类抱怨里：1 条真、1 条假、1 条当时无法判定），
  **不要整批归类**；
- 需要模型判定的东西，先问自己"这个主张能不能被一个脚本判定"；能，就写成脚本，别问模型。
