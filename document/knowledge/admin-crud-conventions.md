# 知识：管理端 CRUD 约定（S4.5 批二）

> 首个落地：套餐 CRUD（`AdminPlanController` / `PlanService`）；后续资产登记/用户管理沿用同一套约定。

## 1. 写路径必失效缓存

- 套餐目录是缓存读（`plan:active:list`，两级缓存）；
- 所有变更（创建/编辑/上下架/删除）**必须 evict** 该键：L1 清 + L2 删 + Pub/Sub 广播；
- 证据：`_c9` 剧本——创建/改价/下架在 `/user/plans` 立即生效（若漏 evict 会读到旧目录）。

## 2. 校验即契约（先校验后落库）

- 名称必填 + 长度上限；类型枚举合法性；
- 价格必填且 >=0；TIMES 必带总次数>0；MONTHLY 必带天数>0；日限次可空但>0；
- 校验失败抛 `RRException`（HTTP 400 + 明确消息），不做"静默修正"。

## 3. 删除策略：有引用禁止删除

- `user_plan.plan_id` 有引用时拒绝删除（提示改为下架）——保护历史购买数据；
- 无引用才物理删除；删除同样 evict。

## 4. 管理端不做缓存

- `GET /admin/plan` 全量（含下架）直读 DB：管理操作需要**强一致视图**，缓存收益低、风险高；
- 只有用户侧目录（`listActive`）走缓存。

## 5. 边界

- 无审计表（管理操作日志）——管理端 RBAC/审计归 S4.6 或后续；当前以应用日志留痕；
- 无分页（套餐量级小）；资产/用户 CRUD 若量大再补分页与批量接口。
