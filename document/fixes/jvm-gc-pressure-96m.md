# JVM 排障故事：96m 堆压测 → GC 信号 → 定位 → 对比（P0-3e）

> 日期：2026-09-16 ｜ 场景：读路径 100 线程 45s 稳态（限流关、同机）
> 证据：`scripts/verify/batch17/_p03e_out.txt`；原件（GC log / jstat / jtl）`diag-archive/p03e-jvm-*`（不入 git）
> 复现驱动：`scripts/verify/batch17/_p03e_jvm_story.ps1`（逐堆生成 .bat 启动；本机 shell 包装对 cmd/start 有等待现象，
> 本次按驱动同款步骤手工执行并归档）

## 1. 现象

同一负载下把堆从 512m 压到 96m：吞吐从 **2,987/s 降到 2,344/s（-21.5%）**，
平均延迟从 **31ms 升到 40ms（+29%）**，错误仍为 0——"没有报错但明显变慢"。

## 2. 定位（两步证据）

| 证据 | 96m | 512m |
|---|---|---|
| GC 暂停次数（45s） | **2,040** | 98 |
| GC 暂停总时长 | **3,996.7ms（占 8.9%）** | 277.0ms（占 0.6%） |
| 单次最大暂停 | 20ms | 9.8ms |
| jstat 老年代占用 | **63.4MB 中占 52.1MB（~82%）**，YGC=85、CGC=30、FGC=0 | 余量充足 |

- GC log：暂停频率 20.8 倍、总暂停 14.4 倍 → 分配速率高 + 堆小 → 年轻代频繁回收、老年代高位。
- jstat：`OU/OC ≈ 82%`，并发 GC（CGC=30）在兜底，未触发 Full GC——所以"不死但很慢"。
- 结论：该服务是**高对象 churn（响应序列化/日志/集合拷贝）**型负载，堆过小直接转化为暂停时间与吞吐损失；
  与"内存泄漏"无关（老年代没有持续增长到 OOM，FGC=0）。

## 3. 处置与验证

- 处置：堆固定 512m（压测）/ 云上 768m（`-Xms256m -Xmx768m`），限流与缓存维持既定基线。
- 验证：512m 同负载 0 错误、暂停占比 0.6%、最大暂停 9.8ms（可接受）；100 线程吞吐 2,987~3,525/s。
- 方法论沉淀：**现象（延迟/吞吐）→ GC log 定量（暂停次数/总时长/占比）→ jstat 老年代占用 → 判断（堆不足 vs 泄漏）
  → 调参复测**。可回答"你调过 JVM 吗/出过什么问题"类追问。

## 4. 边界（如实）

- 未制造 OOM（96m 下 CGC 兜住）；要复现 OOM 可继续降到 ~64m，但非必要（会污染演示环境）。
- 同机压测（JMeter 与平台互抢 CPU）；数字用于**相对对比**（96m vs 512m），不作绝对容量。
- jstat 采样 25 次，展示的是稳态段中盘数据。
